# The 2 MB packages (2, 3, 5) against the Origin 300 package, routine by routine

Read from the IRIX 6.5.30 `l1.bin` (L1 1.44.0). Package numbers and labels follow [personalities.md](personalities.md): 2 `MIPS 2MB image`, 3 `Legacy 2MB image`, 5 `2MB image`; package 1 `Fuel/PE/O300 1MB image` is the reference, shortened to "o300". The routine pairing is [personality-diffs/routines.tsv](../../../evidence/personality-diffs/routines.tsv). The generic 1 MB package is in [personality-base-package.md](personality-base-package.md); how each package maps the brick type to board code is in [personality-board-init.md](personality-board-init.md). Addresses are first-bank body addresses. Grades follow [AGENTS.md](../../../AGENTS.md).

## How the "changed" pairs split

Each changed pair was compared byte by byte, assigning every differing byte to a 32-bit word that holds a flash pointer in both packages or a RAM address in both.

| Package | Changed | Same length, only pointer and RAM words differ | Same length, other bytes differ | Different length |
|---:|---:|---:|---:|---:|
| 2 | 51 | 32 | 4 | 15 |
| 3 | 445 | 53 | 92 | 300 |
| 5 | 423 | 50 | 105 | 268 |

Established for the first column (the classification was computed for every pair of each package). Pairs in the first column are the same code instruction for instruction, moved. The "other bytes" column for package 2 is four pairs, all read below as range-boundary artifacts, not code differences. For packages 3 and 5 the same column was counted but not read pair by pair: a differing byte outside a pointer or RAM word is a different instruction or a range that starts in the middle of an instruction, and the two cases were not separated there. Inferred for packages 3 and 5 that most of those pairs are real code changes, from the size of the added and removed code below.

## Package 2: the generic 1 MB package's code plus the Origin 300 modules

Established from the pairing and the module literals. Package 2 contains every routine of package 0's board code (the controller firmware source unit 12, the controller firmware source unit 11, the controller firmware source unit 18, the controller firmware source unit 24, the controller firmware source unit 43) and the Origin 300 modules the controller firmware source unit 1, the controller firmware source unit 3, the controller firmware source unit 30 and the controller firmware source unit 46, but not the controller firmware source unit 14. Against package 1 it has 95 routines with no partner (35,296 bytes) and 583 added routines (about 540 KB).

Package 1 routines absent from package 2, by module literal: four the controller firmware source unit 14 routines (812 bytes, `0xffe44ff4` to `0xffe458c4`: the Origin 300 node-board code and its bus-select hook), one the controller firmware source unit 21 routine (80 bytes at `0xffe11ce0`, the first part of the request task initialiser, which the pairing split in two; package 2's copy is the whole routine, see the first row below), two the controller firmware source unit 78 routines (64 bytes), one the controller firmware source unit 71 routine, one `fan.c` routine and one `temp.c` routine. The rest (85 routines, 34,216 bytes) cite no source file literal.

Package 2 routines with no package 1 partner, by module literal, largest first: the controller firmware source unit 55 5 routines (2,998 bytes) and the controller firmware source unit 56 8 (2,018), the controller firmware source unit 60 1 (1,736), together the JTAG scan layer; the controller firmware source unit 15 8 (2,564); `pcix.c` 8 (2,536); the controller firmware source unit 72 5 (1,528); the controller firmware source unit 12 6 (1,460); the controller firmware source unit 45 2 (880); the controller firmware source unit 4 1 (848), the controller firmware source unit 5 1 (116), the controller firmware source unit 37 1 (60); the controller firmware source unit 43 1 (412, the second dispatcher read in the board-init note); the controller firmware source unit 36 2 (382); the controller firmware source unit 11 2 (356); the controller firmware source unit 31 2 (332); the controller firmware source unit 18 2 (284); the controller firmware source unit 75 1 (260); the controller firmware source unit 78, the controller firmware source unit 64, the controller firmware source unit 24, `fan.c`, the controller firmware source unit 71, the controller firmware source unit 39 and `temp.c` one each. 520 added routines (539,888 bytes) cite no literal.

## Where each personality is chosen, in one place

Established (see [personalities.md](personalities.md) and [personality-board-init.md](personality-board-init.md) for the reads): no strap, EEPROM jumper or flash record is read to pick board code at run time. The type character is derived from the board's identification EEPROM records (`0xff`, `0xfe`, `0xfd`, `0xfc`), with a persistent setting (key 9) as the fallback, and a dispatcher then calls the initialiser for that character. The flash record only says which packages the updater may offer for a brick type. Each package contains only the board code its type list needs.
