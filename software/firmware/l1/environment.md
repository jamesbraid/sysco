# Origin 300 L1 environmental monitoring and M-Bus reading

The selected Origin 300 L1 1.44.0 image uses the ColdFire M-Bus for more than board identity reads. Its IP45 initialization registers controller-side monitor and I/O expander tables. Environmental tasks then configure monitors, service interrupt reports, read voltages, fan tachometers and temperatures, and turn threshold changes into controller events. These are facts about this software path. The image alone does not name the fitted parts, the CPU clock or any electrical timing.

## IP45 table and startup order

The normal IP45 board-registration path at `0xffe45990–0xffe45ae2` installs a bus-selection callback, 17 logical I/O expander descriptions, six board/memory record routes, three logical monitor descriptions, ten power supply descriptions, one fan control description, five fan tachometer descriptions and two temperature descriptions. Those are **software table counts**. The same startup calls the shared EEPROM scan and monitor initialization before the main boot task creates the general request endpoint (`0xffe4a48c–0xffe4a4b0`, `0xffe10570–0xffe10650`).

The three monitor descriptions at `0xffe45de8–0xffe45e0c` select bus 0 and 8-bit address forms `0x58`, `0x5a`, `0x5c`, respectively (seven-bit forms `0x2c`, `0x2d`, `0x2e`). The descriptions name three node positions. The temperature table at `0xffe45f44–0xffe45f54` references monitor indices 0 and 1. The IP45 high-level monitor interrupt registration covers indices 0–1 at `0xffe45990–0xffe45ae2`, although initialization iterates all three monitor descriptions at `0xffe69958–0xffe69998`. This explains why the two-node sample readout does not establish the purpose or fitted status of the third software route.

The expander descriptions use several even wire address forms in the `0x40` through `0x4e` range and several software bus selectors (`0xffe45c90–0xffe45da0`). The controller-side select callback maps IP45 selectors 6–9 to four DIMM paths and handles selectors 0–5 through a generic selector (`0xffe457fc–0xffe4597e`). The selected firmware drives expander bytes and bit masks through the same serialized M-Bus transfer helpers (`0xffe6562c–0xffe65d34`); front-panel, power and node control routines call those helpers. The table mixes controller paths, logical bit groups and disabled/optional entries. It cannot identify a fitted expander package or electrical channel for each description.

## Environmental state and timing in software

After general and command endpoints start, the main task initializes environmental task 4 at `0xffe10570–0xffe10650`. The environmental initializer at `0xffe2b94c–0xffe2bd2c` creates three interrupt workers and three ongoing monitor workers for power, fan and temperature. It derives each worker's stack allocation from a memory-size threshold, then reads the registered power, fan and temperature table counts. A restart of monitoring at `0xffe2b798–0xffe2b830` checks settings and power-ready state, configures the monitors in power/fan/temperature order (`0xffe291d8–0xffe292b0`), and marks monitoring disabled with a configuration-error state if any group returns an error. The error is combined across entries; this note has not established a one-to-one mapping from a failed M-Bus ACK to the operator's error text.

The selected image initializes two separate interrupt aggregation levels at `0xffe6c1a4–0xffe6c25c`: a high-level input on processor interrupt line 6 and a low-level input on line 1. IP45 registers monitor indices 0–1 on the high worker and expander indices 0–15 on the low worker (`0xffe45990–0xffe45ae2`). The M-Bus transaction-complete IRQ used by the two-wire engine is a separate continuation (`0xffe6d1c8–0xffe6d23c`). The visible wait values are 300 before a management-link condition and 1,500 after it; their units and wall-clock intervals are not established. A callback count of zero after 100 wakes causes temporary masking, and ten empty timed wakes permit re-enabling (`0xffe6c25c–0xffe6c498`). These are software counters, not proven hardware deglitch parameters. Lost ACK and arbitration take different result codes at the M-Bus layer (see [mbus.md](mbus.md)); this note has not followed those codes up into the environmental workers.

Monitor type 1 uses one-byte register reads and writes through the selected M-Bus route (`0xffe681c0–0xffe6865c`, `0xffe6904c–0xffe69844`). The temperature read path obtains one register byte, treats it as a signed value and subtracts a configured offset (`0xffe5e1bc–0xffe5e218`). Its enable/disable and limit configuration write monitor registers through the same route (`0xffe5e24c–0xffe5e280`). This establishes the **software-visible operation width and conversion**, not a measured sensor's accuracy or its fitted chip revision. Fan tachometer and supply records select either monitor registers or expander input bits through their own descriptor types (`0xffe4a8ec–0xffe4aa10`, `0xffe4bdb0–0xffe4bf78`). A normal `env` or `fan` command therefore reads current controller state and can itself trigger live M-Bus reads; request `0x0006` still serves cached board identity state.

The fan interrupt worker attempts five tachometer readings with a software wait value of 200 between attempts. On each successful read it adds the value to a running sum and divides that sum by the current attempt count (`0xffe29dbc–0xffe29df2`). The temperature worker uses the same pattern and 200-unit waits (`0xffe2a078–0xffe2a0ac`). Failed attempts do not update the computed value; a later failure leaves the value from the last successful attempt in place for the threshold comparison. These values are not necessarily averages of five valid samples. A supply threshold worker can recheck a reported out-of-limit reading after waits of 15 and 35 before deciding whether to emit an event (`0xffe29814–0xffe29cec`). A standalone automatic fan worker, if installed by the board callback, loops with a wait value of 500 and can change fan control settings or emit a fault event (`0xffe48f20–0xffe4935c`). Inferred only: the IP45 descriptor's automatic-fan callback is not resolved, so whether this worker runs on the normal IP45 path is unknown (route: find who stores a callback into the fan description built at `0xffe45990`).

Threshold workers track enabled, waiting-for-power, warning and fault states separately. They use cached state to avoid repeating a transition event on each sample. A new voltage fault, low-RPM fan fault or high-temperature fault can start the environmental power-down sequence, while a recovery can clear the local warning state (`0xffe29814–0xffe2a7a8`). The visible task-4 event code families are `0x1000` supply, `0x2000` fan, `0x3000` temperature, `0x4000` environment and `0x4101` countdown. These codes describe emitted packets, not the sensor electrical interface.
