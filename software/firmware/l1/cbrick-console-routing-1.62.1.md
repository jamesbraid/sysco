# The Altix C-brick L1 (1.62.1, `2MB image`): one channel per node, and how the console picks a node

How the ColdFire L1 that serves an Altix 3000 C-brick (type `5`, board `IP41`; [sn2-l1-1.62.1-packages.md](sn2-l1-1.62.1-packages.md)) tells its two nodes apart, where it sends operator input, and what it does with console output from both. The node firmware's side of the same traffic is in the chips repository, `software/firmware/snprom/l1-requests.md`, section "Two PROMs on one L1 console". Grades follow [AGENTS.md](../../../AGENTS.md). Nothing was run.

Source: package 3 (`2MB image`) of the `snxsc_firmware` 1.62.1 container, the 44-byte package header skipped, 1,771,652 bytes, SHA-256 `fdb1a5444e0e11bd6d24bb080b3e5795a2dd340a2146cc1ced74419597d8f339`, loaded flat at `0xffe00000`. Ghidra (68000:BE:32:Coldfire, decompiler as navigation only) located the routines; every statement below was re-read from a Capstone M68K listing of the bytes. Addresses are first-bank addresses; the second bank is `0xf0000` higher (`0xfff2bd4c` is the same routine as `0xffe3bd4c`). Capstone decodes the ColdFire subset in 68040 mode; operands and branch shapes were checked, mnemonics that Ghidra mis-decoded (it shows `FUN_ffe7b80c` with arguments it ignores) were taken from the bytes.

## Answer first

- **A C-brick has two node links, one per node, and the link a frame arrives on is the node's identity.** `0x0003`, `0x000e`, `0x0013`, `0x0009` and the other requests carry no node selector. The L1 derives the slab (node number) from the SCC channel the frame came in on. Established, below.
- **Console input goes to exactly one (slab, subchannel) at a time**, named by one global word. It is set by the `select` command and also moves by itself on every class-2 frame a node sends. With both nodes on the remote console (index 4), slab 0 wins. Established for the routines; the number of slabs the loop scans (2) is inferred.
- **Console output from both nodes is printed in arrival order, one event per frame, with no node tag**, and only while the L1 is in console mode. Established.

## Node links: one SCC channel per slab

**Established** (`SCC init` `0xffe3d374`, group set-up `0xffe3d038`, port open `0xffe3d1c8`; the config tables are 24-byte entries of six words).

- For brick type `5` the init calls the group set-up with **2** entries from the table at `0xffe3f2b4`: `{10, 0, 2, 0, 0, 0}` and `{14, 0, 2, 0, 0, 0}`. For type `O` (`0x4f`, the Opus TIO brick) it passes 1 entry from `0xffe3f29c`, `{10, 0, 2, ...}`. Any other type letter falls out of the init. Word 0 is the software UART device (opened with `0xffe876e4(device, 2)`, one read task `SCC_RT<group><index>` per entry), word 1 selects the transport (0 is the UART read and write pair `0xffe3f0f8` and `0xffe3f1bc`), word 2 the mode. Mode 2 means "take it from setting 8": 1 (PPP-framed) when setting 8 is non-zero, else 0 (raw). The command `syscom protocol ppp|raw` is that setting. Setting 8 is 1 in the blank settings image of the 1.44.0 package 1 body ([settings-window-blank-image.md](settings-window-blank-image.md)); package 3's blank default was not read.
- **Slab is the index of the entry** (read task argument `group << 8 | index`, `0xffe3e764`). `0xffe3d530(slab, subchannel)` builds the tag `slab * 32 + subchannel`; for type `6` (`0x36`) the factor is `0x18` and for `@` (`0x40`) it is `0x14`, every other type uses 32. The inverse routines are `0xffe3cd5c` (slab, a divide) and `0xffe3cda4` (subchannel, a remainder).
- A frame is parsed on its own channel: a class-0 request (`0xffe3e4a0`) and a class-2 event (`0xffe3d650`) both put `tag(channel, header & 0x1f)` into bits 11:5 of the packet's source word. The request dispatcher (`0xffe3f9d4`) recovers slab and subchannel from those bits with the inverse routines.
- **Reply `0x000e` (slab) is that slab.** The case at `0xffe3f9d4` writes status 0 and one integer, the slab from the source word (the type test before it, against `,`, `}`, `.` and `$`, changes nothing). `0x0010` (processors) is per slab too: it logs `SL REQ: slab %d ...` and returns the presence and enable words of the requesting slab. `0x0003` (rack, bay, type) has no per-node part. So the coordinator's guess is right for this L1: the nodes are told apart by the link, and the same request gets a different answer on each. For the model: one UART channel per node, the channel index is the slab.
- Which physical node is wired to device 10 and which to 14 is a hardware question this image does not answer (unknown).

## Raw mode

**Established** (`0xffe3d554`). In mode 0 every read from the node's UART becomes one class-2 event whose payload is the raw bytes and whose tag is `slab * 32 + 4`, so raw input is always console 4 of that slab. Output in mode 0 is the bare character, with no header and no FCS (`0xffe3d868`, the `+4 == 0` branch). In PPP mode a class-2 frame's payload has its NUL bytes removed before it is forwarded (`0xffe3d650`).

## Which node gets input

**Established** for the routines named (`0xffe3bd4c` console input, `0xffe3bb4c` route, `0xffe3abf8` and `0xffe3ad14` select, `0xffe3d650` inbound event, `0xffe3d868` outbound request, `0xffe15f10` the `select` command).

1. One word, `0x30006a70`, is the console target: this brick's rack and bay in bits 31:12 (unless the select named another brick), `tag(slab, subchannel)` in bits 11:5 and the SCC group in bits 4:0. Each typed character becomes one request to task 5 of that address, carrying the character (`0xffe3bb4c`). If the L1 gets no answer from its own link writer within 3000 ticks (the message prints 30.00 seconds; the tick length was not read) it prints `ERROR: no console response from ...`; the node sends no acknowledgement (the answer is the L1's own transmit status).
2. The link writer (`0xffe3d868`) sends one frame per character, header byte = the subchannel (class bits clear), then the character; in PPP mode through the framer, in raw mode as the bare byte. A brick whose power state is not on gets `WARNING: power on ... appears off` instead (type `?` skips the test). Same shape as the ARM L1 ([sn2-prom-link-1.62.1.md](sn2-prom-link-1.62.1.md)).
3. **The target follows the nodes.** On every class-2 frame, `0xffe3d650` records the frame's subchannel (`header & 0x1f`) as that slab's current subchannel (a byte per slab in the table behind `0xffe72ce8`/`0xffe72e44`), then picks the **lowest slab whose recorded subchannel is 4**; if none has 4 it picks the sender with the frame's own subchannel. It calls `0xffe3abf8(group, slab, subchannel)` with that, which stores the target word, and logs `INFO: console subchannel changed: ...` only when the word changed and the debug switch is on. The slab loop runs to the word at `0x300034b4`, or 1 if that is 0. For type `5` the brick-operations initialiser (`0xffe59c14`, chosen by the type dispatch at `0xffea8ba0`) stores 2 at `+0x18` and at `+0x94` of the operations record; that `0x300034b4` is `+0x94` of that record is inferred, not read.
4. **`select` overrides it only until the next class-2 frame.** `select subchannel console` sets slab 0, subchannel 4; `select subchannel a|b|c|d` sets slab 0, subchannel 0 to 3; `select subchannel <number>` and `<word>` (`console<n>`, or a slab and subchannel) set others; `select <rack> <slot> ...` retargets another brick (`0xffe3ad14`); `select` alone prints `console input: ...` and `console output: ...` with `DISABLED`, `filtered` or `not filtered`. Nothing in the routines locks the choice, so the next inbound event replaces it (established for the code path; the reading that no other guard exists rests on the callers of `0xffe3abf8`: the `select` handler, two sites at `0xffe3ae52` and `0xffe3ae78`, and `0xffe3d650`).

Consequences for two PROMs. Frames with header `0x40 | slice` (the PROM's `p` console) make that slab's recorded subchannel 0 to 3, so input follows whichever node spoke last. Once a node has sent a frame with header `0x44` (the `r` console, index 4) its recorded subchannel stays 4 until it sends another index, and input then goes to the lowest such slab: both nodes on index 4 means slab 0, even while slab 1's PROM is the one waiting for a key. A key typed before any node has sent a frame goes to the initial target, this brick with the subchannel the SMP init read from the module record (`0xffe3b3a8`; its value was not read).

## What happens to output

**Established** (`0xffe3affc`, the SMP write task, and `0xffe3af0c`, the operator-port writer that expands LF to CR LF).

- A forwarded event reaches the operator only when the L1 is in **console mode** (state word `0x300063b0` equal to 1). The task sets state 3 at start and `L1 command processor engaged, <CTRL-D> to exit.` also sets 3; Ctrl-D (`0x04`) in state 3 enters console mode for the brick types in the list at `0xffe3bd4c` (it includes `5`) and prints `entering console mode ..., <CTRL_T> to escape to L1`; Ctrl-T (`0x14`) in console mode drops to state 2 (the L1 prompt), and Enter on a command line there returns to console mode (`returning to console mode ...`). In states 2 and 3 node output (source task 5, the node links) is discarded, not queued. A per-slab capture log exists for the `log` and capture commands (`SysCom_2m.c`); what it keeps was not read.
- Events from the node links are written as they arrive: each string argument goes through `0xffe3af0c` as is, one event per node frame (at most 127 payload bytes), **no slab prefix, no per-slab buffer, no reordering**. Two nodes printing at once interleave at frame boundaries.
- Two switches can stop it. `select disable` sets setting `0x81`, and while it is non-zero `0xffe3d650` does not forward events at all (shown as `DISABLED`). `select filter on` sets setting 10; with it set the write task compares the event's source word, as a whole word, with the rack and the bay of the target separately and drops the event on a mismatch. As written the comparison cannot match for any real word (read as a bug or a placeholder in the shipped code), so filter on drops node output. Inferred: the intent of the filter is not stated anywhere.
- Source task 4 (events that are not from the node links) is accepted only if its rack and bay equal the brick's own (words `0x300012cc`, `0x300012d0`, set at SMP start). What produces task 4 events was not read (unknown).
