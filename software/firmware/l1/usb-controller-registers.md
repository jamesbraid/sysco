# Origin 300 L1 1.44.0: USB controller accesses

The selected Origin 300/IP45 L1 image drives a device-side USB controller on the ColdFire bus. The control-request reading covers the USB requests; this note follows the lower byte-register operations that serve them.

## Evidence and limits

The body loads at `0xffe00000` (reset vector `0xffe00400`). The second firmware bank has corresponding code but is not wholly byte-identical; these claims are tied to the first bank of L1 1.44.0.

Hint, not a finding: Agere's USS-820D USB Device Controller data sheet, revision 4, June 2001. Its accessible front matter establishes a byte-addressed local-processor register interface, programmable endpoints and FIFOs, integrated D+/D− transceiver, and a firmware-controlled D+ pull-up supply. The data sheet does not identify the fitted controller package, and no image names it.

## Startup chooses one of two lower-controller paths

The image has two software controller slots. Before probing, the startup routine (`0xffe55198`–`0xffe55252`, read in full) programs the ColdFire on-chip registers relative to the MBAR value held in RAM at `0x300002e8` (`0x10000000`): for slot zero it writes the 16-bit value `0x4000` at `MBAR+0x88`, zero at `MBAR+0x8c` and `0x0953` at `MBAR+0x92`; for slot one it writes byte `0x8c` at `MBAR+0x16`, `0x6000` at `MBAR+0xa0`, zero at `MBAR+0xa4` and `0x0953` at `MBAR+0xaa`. Inferred from the public MCF5206E manual's register map (not read from the image): these are the chip-select address, mask and control registers of chip selects 3 and 5, mapping slot zero to `0x40000000` and slot one to `0x60000000`, with the same control word `0x0953` for both, and the byte at `MBAR+0x16` is an interrupt control register for slot one. The startup then checks an existing software count: a positive count attempts slot zero at ColdFire byte base `0x40000000`; count exactly two also attempts slot one at byte base `0x60000000` (`0xffe55198`–`0xffe55252`). Before choosing a driver callback, each attempt writes a test value to base offset `0x1b` and reads byte offset `0x18`. If the revision byte is `0x81`, it calls an unresolved callback pointer held in RAM at `0x300006f4`. Otherwise it enters the visible USS-820-family probe (`0xffe6db6c`–`0xffe6dc08`; disassembly confirms the branch). This choice is material: the visible register sequence below is conditional on **not** reading `0x81`, and the alternative callback's implementation and silicon identity were not recovered from this trace. The software count and two address constants do not prove two fitted devices, package location, or which slot connects to the rear type-B port.

The visible probe accepts revision bytes `0x10`, `0x11`, and `0x13` quietly. Any other byte with high nibble one is accepted with a warning; another high nibble fails. It then writes each even byte from zero through `0xfc` to offset `0x1b` and immediately reads it back, failing on the first mismatch (`0xffe70968`–`0xffe70a98`). The firmware's diagnostic wording calls this path USS-820 and describes `0x18` as a revision and `0x1b` as scratch. That supports the **software's intended controller family**, not a verified IP45 package or precise chip revision. A part that reads revision zero, or always `0x13`, would not show the probe behavior read from the image.

The controller-parent ColdFire interrupt-mask write is separately 16-bit at parent base offset `0x36` (`0xffe6e818`–`0xffe6eab8`), after callback and deferred interrupt work are registered. It must not be folded into the USB controller's byte-register map. The image registers distinct low-level interrupt paths for software slots zero and one and shares higher-priority reset, control, read and write workers (`0xffe6e818`–`0xffe6eab8`). Unknown: the interrupt line wiring and polarity; the interrupt-control register write for slot one above and the mask write at parent offset `0x36` are the software side of it (route: the MCF5206E manual's interrupt controller chapter and MAME's MCF5206E core).

## Reset, address and endpoints

The visible reset callback disables its active condition, optionally toggles the byte at `0x1c` with a short wait, clears address and global interrupt state, initializes each of eight logical endpoint selections, then enables endpoint-zero state and interrupt bits (`0xffe70ae0`–`0xffe70b98`). A separate operation clears endpoint-zero FIFO state and stalls or resets its transfer state (`0xffe70b98`–`0xffe70bd0`). Configuration one changes the endpoint-one and endpoint-two FIFO allocation fields and resets their per-endpoint state; configuration zero clears them (`0xffe70bd0`–`0xffe70c50`). The firmware declares only EP0 plus bulk OUT 1 and bulk IN 2 in its descriptors; initializing eight internal selections is not evidence of eight external endpoints.

`SET_ADDRESS` makes two lower calls around the zero-byte IN status stage. The first validates that the requested address fits seven bits; the visible callback does not write a register for that call. Only after validation and the status stage succeed does the second call write the address byte at offset `0x10` and update the software address state (`0xffe6f920`–`0xffe6fa78`, `0xffe6d678`–`0xffe6d70c`, `0xffe71454`–`0xffe7156a`). An early address write is therefore a distinguishing error. A failed validation call or status stage prevents the after-status action in the visible control dispatcher. Bus timing is set by the chip-select control word above, whose fields are the MCF5206E manual's; the host-observed completion is outside the image.

Endpoint-zero receive processing examines setup/transfer flags and drains the receive FIFO. The interrupt callback separately handles endpoint-zero setup/data activity and endpoint-one/two read/write completion, disabling uninterested enable bits and recording repeated inactive interrupts (`0xffe70c50`–`0xffe71334`, `0xffe7156c`– `0xffe716de`). These are controller-side stages.
