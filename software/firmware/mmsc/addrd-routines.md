# Address daemon routines (`addrd`)

The 29 routines defined in the `addrd` object of `mmscfw.bin`, IRIX 6.5.30 (MMSC 2.3), one entry each. The protocol they implement is summarised in [rack-election.md](rack-election.md); the table they maintain is in [identity-table.md](identity-table.md). Sizes count code up to the last `ret`; the bytes to the next symbol are string literals. "Identity" below is the 28-byte record described in [identity-table.md](identity-table.md); "message" is the 48-byte payload of [rack-election.md](rack-election.md).

## Set-up, task loop and the two ways in

- `addrdInit` (`0x10dba0`, 307 bytes). Starts the address daemon's plumbing in this order: `pipeDevCreate("/pipe/addrd", 23 messages, 62 bytes)` at `0x10dbac`, where a failure with errno `0xd0006` (the device already exists) is accepted and any other failure is logged and returns -1; opens the pipe write-only into the global `addrdEtoAFD` (`0x1b07a0`, initial value -1); creates a watchdog into `addrdElectionTimer` (`0x1f2b78`); `lstInit` on the election list `addrdElectionList` (`0x1e2870`); `semMCreate` with option 1 into the guard `addrdElectionSem` (`0x1f65ac`); spawns task `tAddrD` (priority 25, options 0, stack 20,000, entry `addrd`); and only if the spawn succeeded registers `addrdEtherInputHook` with `etherInputHookAdd`. Each failure is logged by name and returns -1; success returns 0. Established.
- `addrd` (`0x10e160`, 605 bytes). The task body. Opens `/pipe/addrd` read-only (failure returns -1), then loops on `select(256, {pipe}, 0, 0, 0)` with no timeout. A `select` error other than errno 4 is logged, the pipe is closed and the loop count is decremented, which ends the loop. On a readable pipe it reads up to 62 bytes: a negative read or end of file is logged and closes the pipe and ends the loop; a short or long read is logged ("should be 62") and ignored. A good message is first upgraded in place (payload version 0 or 1 gets module numbers `0xffffffff, 0xffffffff` and version 2; version 0 to 2 gets capability flags 0 and version 3), then the type at payload +4 less one indexes a seven-entry jump table at `0x10e300`: 1 `addrdProcessIdentityMsg`, 2 `addrdProcessQueryMsg`, 3 `addrdProcessAssignMsg`, 4 `addrdProcessElectionStartMsg`, 5 `addrdProcessElectionEndMsg`, 6 `addrdProcessRequestRackIDMsg`, 7 `addrdUpdatePartInfo`. Any other type is logged as unknown and ignored. The handlers' return values are discarded. Returns 0 when the loop ends. Established.
- `addrdEtherInputHook` (`0x10e620`, 73 bytes). The Ethernet input hook, called by the interface driver with (interface, frame, length). Tests the 16-bit word at frame +12 against `0x801`; if it matches, writes the whole frame (length bytes) to `addrdEtoAFD`, logs "Write to address daemon failed" if fewer bytes were written, and returns 1 so that the frame goes no further. Any other frame returns 0. The word is two bytes `01 08` on the wire ([rack-election.md](rack-election.md)). Established.
- `addrdLocalMsg` (`0x10e030`, 104 bytes). Sends a message to the local task. Zeroes a 62-byte buffer, stores `0x108` in the 16-bit field at +12, copies the 48-byte message passed as the argument to +14, and writes 62 bytes to `addrdEtoAFD`. Returns 0 when the write was 62 bytes; otherwise logs "addrdLocalMsg write to address daemon failed" and returns -1. Established.
- `addrdBroadcastMsg` (`0x10ded0`, 120 bytes). Sends a message to every MMSC. Builds a 14-byte header on the stack, copying the 6-byte `ffscMACAddr` into the source field first and then the 6 bytes at `etherbroadcastaddr` into the destination field, stores `0x108` in the type field, and calls `etherOutput(ffscNetIF, header, message, 48)`. Returns 0 if `etherOutput` returned 0; otherwise logs "Unable to broadcast ethernet packet" and returns -1. The six bytes at `etherbroadcastaddr` are all `0xff`. Established.

## Moving an identity in and out of a message

- `addrdExtractIdentity` (`0x10df50`, 81 bytes). Copies message fields to an identity: the dwords at message +8 and +0xc to identity +0x14 and +0x18, 8 bytes from message +0x20 to identity +0, 4 bytes from message +0x28 to identity +8, the dword at message +0x2c to identity +0xc and the dword at message +0x1c to identity +0x10. Takes the message first, the identity second. Returns nothing. Established.
- `addrdInsertIdentity` (`0x10dfb0`, 81 bytes). The reverse copy: identity +0x14 and +0x18 to message +8 and +0xc, identity +0 (8 bytes) to message +0x20, identity +8 (4 bytes) to message +0x28, identity +0xc to message +0x2c and identity +0x10 to message +0x1c. Takes the message first, the identity second. It leaves message +0 to +7 and +0x10 to +0x1b alone, so every caller sets the version and type itself and the +0x10 to +0x1b bytes go out as whatever was on the sender's stack. Established.

## Election plumbing

- `addrdElectionStart` (`0x10e5b0`, 57 bytes). Builds a message on the stack with version 3 and type 4 (the other fields are not written) and passes it to `addrdLocalMsg`. Returns 0 on success and -1 if `addrdLocalMsg` fails. Established.
- `addrdElectionEnd` (`0x10e570`, 57 bytes). The same with type 5. Established.
- `addrdElectionTimerPop` (`0x10e5f0`, 14 bytes). The watchdog's routine: calls `addrdElectionEnd`, ignores the result and returns 0. It only queues a message, so the work of ending the election runs in `tAddrD` and not in the watchdog's context. Established; the reason for the split is inferred.
- `addrdStartElectionTimer` (`0x10f0d0`, 67 bytes). Calls `wdStart(addrdElectionTimer, 2 * sysClkRateGet(), addrdElectionTimerPop, 0)`, a two-second delay. A negative result is logged ("Unable to start/restart election timer") and returns -1; otherwise 0. Called again while the timer runs, `wdStart` takes its `windWdStart` path with the watchdog's state field equal to 1 and hands the new expiry to a different method of the tick queue (offset `0x1c`) than the one used for a fresh start (offset `0x10`); that the second method re-queues the running timer is inferred from the name `windWdStart` and the branch, the queue method itself was not read. Established for the call; inferred for the restart.

## Handlers for the received messages

- `addrdProcessIdentityMsg` (`0x10eb10`, 201 bytes). Type 1. Extracts the identity; if its unique ID equals `ffscLocal`'s, logs "Received ADDRD IDENTITY message for local unique ID" and returns -1 (so a frame looped back to its sender is harmless). Otherwise `identUpdate`; a negative result returns -1. If the election flag `addrdElectionDay` (`0x1e238c`) is set, calls `addrdStartElectionTimer` and returns -1 if that fails. With debug bit 0 of `ffscDebug` set prints "ADDRD IDENTITY - new" or "- update" and the identity. If `ffscIsMaster` is set, runs `addrdResolveConflicts`, logging "Address daemon conflict resolution failed" on a non-zero result (the result is not returned). Returns 0. Established.
- `addrdProcessQueryMsg` (`0x10ec40`, 286 bytes). Type 2. Stamps `addrdLastQuery` (`0x1f2b70`) with `clock_gettime(0)`. Extracts the identity, ignores one with the local unique ID (logged, -1), runs `identUpdate`, restarts the timer if the election flag is set, prints the identity under debug bit 0, then `taskDelay(3)`, builds a type 1 message from `ffscLocal`, broadcasts it, calls `addrdStartElectionTimer` and sets `addrdElectionDay` to 1. Returns 0, or -1 at any failed step. Because it stamps the time on every QUERY, an MMSC that joins late re-opens the question for everyone: every peer treats entries older than that stamp as stale. Established.
- `addrdProcessRequestRackIDMsg` (`0x10edb0`, 236 bytes). Type 6. Extracts the identity, `identUpdate`, restarts the timer if the election flag is set, prints under debug bit 0. Then, only if `ffscIsMaster` is set: `identFindConflictingRackID` on the requester; if some other entry has the requester's rack ID, copies that entry's 28 bytes to the stack, sets its rack ID to the result of `addrdFindUnusedRackID` (logging "Unable to assign new rack ID to" and still continuing if that is -1) and calls `addrdAssignNewIdentity`. Returns 0, or -1 for a failed `identUpdate`, timer start or reassignment. Established.
- `addrdProcessAssignMsg` (`0x10e760`, 129 bytes). Type 3. Parses the identity out of the message. When the unique ID at message +0x20 names this MMSC, the identity goes to `addrdUpdateLocalIdentity`, and a failure there logs a warning that the local identity could not be updated. Debug bit 0 gates a line "ADDRD ASSIGN:" with the identity in that case, or "Ignored ADDRD ASSIGN:" otherwise. The routine returns 0 on either branch. Established.
- `addrdProcessElectionStartMsg` (`0x10ea10`, 140 bytes). Type 4. Records the current time in `addrdLastQuery`. With debug bit 0 set it prints a line giving the start time of a master election, in seconds and nanoseconds. It then composes a type 2 frame from `ffscLocal`, sends it to the broadcast path, arms the election timer and writes 1 to `addrdElectionDay`. The result is 0, or -1 when a step fails. The type 2 handler touches the table and sleeps before replying; this one does neither. Established.
- `addrdProcessElectionEndMsg` (`0x10e870`, 374 bytes). Type 5. Debug bit 0 gates the line a line marking the end of a master election. It calls `identCleanOldEntries(&addrdLastQuery)`; a non-zero return makes the routine return -1, although it otherwise always returns 0. `ffscMaster` comes from `identFindMaster()`. When that master is the local identity, `ffscIsMaster` becomes 1. When no master exists (logged as a message that no master could be found) or another MMSC holds the role, `ffscIsMaster` becomes 0. The routine then waits on `addrdElectionSem` for up to one second; a timeout is logged and returns -1. It walks `addrdElectionList` from the head. A record stamped later than `addrdLastQuery` ends the walk. A record stamped earlier or equal is unlinked (logging a line naming the start time of an election that has concluded under debug bit 0) and its semaphore, the dword at record +8, is released. Afterwards it releases `addrdElectionSem`, clears `addrdElectionDay`, and when the local MMSC is master it runs `addrdResolveConflicts`; a failure there is logged but not returned. Returns 0. Established.
- `addrdUpdatePartInfo` (`0x10d750`, 161 bytes). Type 7. Clears a 128-byte buffer. If `contains_module(&partInfo, message+0xc, message+8)` reports the pair already present, it returns 0 at once. A null `partInfo` (`0x1b1050`, a pointer, 0 at load) gives -1. Otherwise it writes `"P %d M %d C"` when message +0x10 is non-zero, or `"P %d M %d"` when that word is zero, with the partition from message +0xc and the module from message +8, and passes the text to `update_partition_info(&partInfo, text)`. Returns 0. `contains_module` and `update_partition_info` belong to the partition code, which was not read here. Established for this routine.

## Reassigning an identity

- `addrdAssignNewIdentity` (`0x10e470`, 244 bytes). Takes an identity holding the new values. It looks the unique ID up with `identFindByUniqueID`; with no match it logs an error for an identity assignment aimed at an unknown MMSC and returns -1. When the match is the local ID, it applies the identity through `addrdUpdateLocalIdentity` with no broadcast, returning 0, or logging a warning that the new identity could not be set and returning -1. For a remote ID it builds a type 3 frame and broadcasts it; a broadcast failure logs a warning, naming the target ID, that the assignment failed and returns -1. On success the 28 identity bytes are copied into the table entry, so the master's copy already matches, and debug bit 0 prints a debug line announcing an assignment to a remote MMSC. Returns 0. Established.
- `addrdUpdateLocalIdentity` (`0x10ddd0`, 220 bytes). Takes an identity for the local MMSC. It compares four fields against `ffscLocal` and applies each one that differs: the IP address through `identSetIPAddr`, the rack ID through `identSetRackID`, the capability flags through `identSetCapabilities`, and the two module numbers through `identSetModuleNums`. When the IP address, rack ID or capability flags changed, or the module numbers differ, it runs `identUpdate` on the argument and, if that succeeds, broadcasts a type 1 frame carrying the argument's identity. Setter return values are discarded. With no differences it returns 0 immediately. A change confined to the module numbers still reaches the update and the broadcast. Returns 0 on success and -1 when the update or the broadcast fails. Established.
- `addrdRequestRackID` (`0x10dd30`, 156 bytes). Takes an identity whose rack ID is the one requested. It calls `identSetRackID` on the rack ID at identity +0xc (failure logs and returns -1), then `identUpdate` on the whole identity (failure is only warned about). It builds a type 6 frame from `ffscLocal`, not from the argument, because the rack ID is already in `ffscLocal` after the first call. If `ffscIsMaster` is set it delivers that frame to the local task first (failure returns -1), then broadcasts it. Returns 0 or -1. Only caller: `cmdRACKID` (call at `0x114d61`), which first requires the operator's authority value (user record +0x20) to exceed 999 and exactly one rack to be addressed. Established.

## Searching for free values

- `addrdFindUnusedIPAddr` (`0x10e670`, 87 bytes). Takes a 4-byte output. Host numbers from `0x10` through `0xfffffe` are tried in turn: each is combined with the network number (the dword at `ffscNetInfo`+4, `0x1e28b4`) by `inet_makeaddr_b` and checked with `identFindByIPAddr`. The first address with no entry goes into the output and the routine returns 0; if none is free it returns -1. Established.
- `addrdFindUnusedRackID` (`0x10e6d0`, 50 bytes). Scans rack IDs 1 through 21 (`0x15`) and returns the first one `identFindByRackID` does not find. If all are taken it returns `0xffffffff`. Established.

## Conflict resolution

- `addrdResolveConflicts` (`0x10ef00`, 83 bytes). Refuses unless `ffscIsMaster` is set: it logs a refusal logged when a non-master tries conflict resolution and returns -1. For the master, it runs `identScanForConflicts` with `addrdResolveIPAddrConflict` and `addrdResolveRackIDConflict` as the two resolvers. A zero result gives 0; anything else logs a failure line for conflict resolution and gives -1. Established.
- `addrdResolveIPAddrConflict` (`0x10ef80`, 120 bytes). Receives two identities with the same IP address. The same identity can arrive twice when its host part is 15 or lower. The entry with the lower unique ID is kept and the other is renumbered; when both arguments carry the same ID, the first one is renumbered. The chosen copy goes onto the stack and gets a fresh address from `addrdFindUnusedIPAddr`. On success the routine returns whatever `addrdAssignNewIdentity` returns. With no free address it logs a failure line for an IP conflict that stays unresolved and returns 1, which the scan reads as unresolved and skips. Established.
- `addrdResolveRackIDConflict` (`0x10f020`, 137 bytes). The same shape for rack IDs: the identity with the higher unique ID is copied, its rack ID is set to `addrdFindUnusedRackID`, and `addrdAssignNewIdentity` is called. If no rack ID is free, logs "Unable to assign rack ID to <id>" and returns -1, which stops the whole scan. Established.

## Election control

- `addrdElectMaster` (`0x10d9a0`, 306 bytes). Takes no argument. Creates a binary semaphore (`semBCreate(0, 0)`, empty) and `clock_gettime(0)` into a list record on the stack (the semaphore at record +8, the time at +0xc). Takes `addrdElectionSem` for one second (failure: logs "Unable to acquire election list guard semaphore", deletes the semaphore, returns -1), appends the record with `lstAdd`, gives the guard. Calls `addrdElectionStart` (on failure logs "Unable to start election", retakes the guard for one second, removes the record, deletes the semaphore and returns -1; if the guard cannot be retaken it logs "Unable to retrieve aborted election request" and returns -1 with the record still listed). Then `semTake(record semaphore, forever)`; if that returns non-zero logs "Election request terminated abnormally", removes the record under the guard and returns -1; otherwise deletes the semaphore and returns 0. The semaphore is given by `addrdProcessElectionEndMsg`, which removes the record, so on success the record is already off the list. Only caller: `ffscInit`. Established.
- `broadcastPartitionInfo` (`0x10d870`, 138 bytes). Argument: the head of a list of partition records. Takes the mutex `part_mutex` (`0x1f6920`) forever, then for each record and each of the module numbers in it (the count at record +0x400; the numbers at +4 onward) calls `addrdSendPartitionInfo` with the partition number (record +0), the module number and a flag that is 1 when the module number equals the dword at record +0x404, then follows the link at +0x40c. Gives the mutex and returns 0. The meaning of the dword at +0x404 belongs to the partition code and was not read; it is probably the partition's designated module. Callers: `cmdSCAN`, `cmdPARTSCAN`, `SelectPartitions`. Established for this routine; the +0x404 meaning is inferred.
- `addrdSendPartitionInfo` (`0x10d810`, 85 bytes). Argument: three dwords (partition, module, flag). Builds a type 7 message with the module at +8, the partition at +0xc and the flag at +0x10, broadcasts it, and on failure writes "broadcast failed." with `ffscDebugWrite` and returns -1; otherwise 0. Established.
