# scmsg: write one message to the front-panel display

Read from `root/6.5/sbin/scmsg` (IRIX 6.5 Foundation 1, 9,596 bytes, SHA-256 `92a124eee0e14ebf...`), whose only routine of its own is `main` (`0x10000c38`, 456 bytes). The 6.4 Origin build (`root/6.4-origin/sbin/scmsg`, 9,364 bytes) has the same `main` structure and the same stores and write count; its format string was not located. Grades follow [../../AGENTS.md](../../AGENTS.md).

- **Arguments.** Exactly one argument is required; otherwise it prints "Usage: scmsg string_to_display" to standard error and exits with status 1 (`0x10000c54`-`0x10000c84`, strings at `0x10011000`). **Established.**
- **Frame.** It builds three fixed bytes `0x18`, `'S'`, `'M'` (escape, set, message item: the same bytes as `display_string` in [daemon-wire.md](daemon-wire.md)), copies the argument one byte at a time starting at offset 5, limited to 40 bytes (`min(strlen, 40)`, evaluated again on every pass: stores at `0x10000d8c`, bound at `0x10000cbc`), puts a line feed (`0x0a`) after the text at offset `5 + n` (`0x10000cfc`), formats `n` with `"%2x"` (the format at `0x10011120`; note the space padding, where the daemon uses `"%02x"`) and stores the two resulting characters at offsets 3 and 4 (`0x10000d18`, `0x10000d20`). **Established.**
- **Write.** It opens `/dev/sysctlr` read-write (flag value 2, string at `0x10011020`); if the open fails it prints "scmsg: Can't open /dev/sysctlr" and exits with status 1. It then writes `n + 4` bytes of the frame, closes the device and exits 0 (`0x10000d2c`-`0x10000d4c`). It does not read a reply, issues no `ioctl`, and does not probe the length mode that the daemon negotiates. **Established.**

The count and the frame disagree. The frame built is `n + 6` bytes long (escape, `S`, `M`, two length characters, `n` text bytes, line feed), but only `n + 4` bytes are written, so the last text character and the line feed are never sent; the two length characters hold `n`, where `display_string` stores `n + 4`. What a controller does with such a frame is **unknown**: nothing in `root/` shows the controller side. Both builds write `n + 4`. **Established** arithmetic; the consequence is **unknown**.
