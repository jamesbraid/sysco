# ARM Linux L1: serial ports, flash access, scan port and the router frame

The `l1` program of the Linux 2.6 packages reaches its hardware through a small set of layers that [arm-programs.md](arm-programs.md) only names: a UART layer over character devices, a console wrapper, a flash layer over the MTD devices, the JTAG scan port, the external-interrupt tasks and the framing of router packets. This note reads those routines.

**What was read.** `/stand/sysco/bin/l1` of the 1.48.1 Linux 2.6 package (`patches/SG0007149:l1#6`, sha256 `61274890f8ba1708b1380a8716e90060d48c22b2505eebf27255744123cdf96e`, 32-bit little-endian ARM, dynamically linked) was read instruction by instruction. The program exports its routine names, so routines carry them. Addresses are virtual addresses in that executable. Where the 1.44.0 Linux 2.6 build (`6.5.30:l1#6`, sha256 `b33154e53b00...`, a different file) has the same name, its address and size are given and the difference is said; its bodies were not otherwise re-read. Grades as in [arm-linux-packages.md](arm-linux-packages.md). The Linux request numbers named below follow the published Linux headers and are a hint until the kernel side is read; the numbers themselves are read from the instructions.

**Reading conventions.** The program's own logging call takes a severity (9 is used for start-up and fatal conditions, 3 and 1 for run-time errors), a source file name, a line number and a message. `nvramLogFinsert` writes a formatted line into the NVRAM log.

## UART layer (`uart.c`)

The layer keeps up to 36 port records of 264 bytes each (`uart_state` at `0x32e498`, count at `0x32e494`). A record holds: the read descriptor (+0x00), the write descriptor (+0x04), the port number (+0x08), the port kind (+0x0c), a 28-byte configuration block (+0x10 to +0x2b), the line speed given at initialisation (+0x2c), a flag byte (+0x31) and the task that holds the read side (+0x34) and the write side (+0x38). Established from the field accesses in the routines below.

### The device-path table (`0x1ab748`)

- **Port to device path** (`0x1ab748`, 47 words, 1.48.1). Index 0 and 1 are null. Indexes 2 to 4 name `/dev/ttyS0` to `/dev/ttyS2`; 5 to 36 name `/dev/l1io_ni0` to `/dev/l1io_ni31` (the node links); 37 to 40 name `/dev/l1io_ii0` to `/dev/l1io_ii3`; 41 to 46 name `/dev/l1io_jb0` to `/dev/l1io_jb5`. `uartOpen` indexes this table by port number. Port 1, with a null entry, is the console and is handled specially (see `uartOpen`). The cramfs of the 2.6 packages has the matching nodes: `l1io_uart0` to `l1io_uart31`, `l1io_ni0` to `l1io_ni31`, `l1io_ii0` to `l1io_ii3` and `l1io_jb0` to `l1io_jb5` are character devices with major 199 (the node and jack links at minor 40 to 65 and 100 to 111, the generic UARTs at minor 0 to 19 and 80 to 91; see [../inventory/arm-linux-files.tsv](../inventory/arm-linux-files.tsv)). That the `l1io_ni`, `l1io_ii` and `l1io_jb` families are the router's node, interconnect-interface and jack links is inferred from the names. Established for the table; inferred for the roles.

### Routines

- **`uartInit`** (`0x1173a4`, 696 bytes). Takes the port number, the port kind and the line speed. If 36 or more records exist it logs `too many UART devices configured!`; if a record for the port exists it logs `UART port %d already configured!` (whether a severity-9 log call ends the program was not read; the code after each call continues into the setup). It takes the next record, zeroes its 264 bytes, stores the port (+0x08), the kind (+0x0c) and the speed (+0x2c), and sets both descriptors to -1. It then sets the flag byte (+0x31) by port range: ports 5 to 36 store 1 when the speed argument is not `0x2dc6c0` (3,000,000); ports 37 to 40 store 1 when it is not `0x1a286` (107,142); ports 41 to 46 store 1 when it is not `0xe100` (57,600); other ports leave the flag zero. Last, it opens `/dev/mem` read-write with `O_SYNC` (flags `0x1002`), maps 0x100 bytes of physical `0x08000000` (the first of the board FPGA's windows of [arm-programs.md](arm-programs.md); shared read-write) into a global pointer at `0x3260f0`, and exits the process with status 1 on either failure (messages `uartInit: can't open /dev/mem, errno %d` and `uartInit: can't mmap FPGA UART regs, errno %d`). Returns the record. Established. What the three speeds mean is not read: the table sets the flag when the speed is anything other than the one listed, and `uartOpen` turns the flag into a driver request (below), so the flag marks ports that need an extra driver setting at a non-default speed (inferred). The 1.44.0 build of `uartInit` is 464 bytes (`0x10ebe4`), has the same port-range tests and compare values `0x1a286` and `0xe100`, and contains no `open` or `mmap` call, so it does not map the FPGA window.
- **`uartOpen`** (`0x11765c`, 1288 bytes). Arguments: port number and open flags. Finds the record by port (null when none). The access mode is the low two bits of the flags. Mode 0 (read) succeeds only when the read side is free or already held by the calling task, and records the caller (`taskCurrent`) in +0x34. Mode 1 (write) does the same for +0x38. Mode 2 (both) succeeds when neither side is held, or when the caller holds both. A failed claim returns null. Port 1 (the console) is special: if its read descriptor is still -1 and a side was claimed, it sets the read descriptor to 0 and the write descriptor to 1 and calls the console setup routine at `0x1184c0` with descriptor 0 and speed code `0xf`; no device node is opened. Every other port opens the table path with the caller's flags (a failed open other than `EINTR` is logged as `%s: open(%s) failed: %s [%d]`, returns null; `EINTR` retries). The descriptor goes into +0x00 for a read claim and +0x04 for a write claim. For records of kind 1 or 5, it issues request `0x80047503` with argument `0x400` on the read-side descriptor (the write one when no read side was claimed), and closes the port and returns null on failure. When the flag byte (+0x31) is set it issues `0x80047506` with argument 1 on the same descriptor, with the same failure handling. When the open flags include `0x2000` (the Linux asynchronous-I/O flag, hint) it issues `0x80047501` with argument 1, again closing on failure. Returns the record. Established. The meanings of the four driver requests are not read; their kernel side is not in the package files. The same size, `1288`, is the 1.44.0 build's (`0x10edb4`); bytes not compared.
- **`uartClose`** (`0x117b64`, 508 bytes). Arguments: record and open flags. Releases the side or sides named by the low two bits of the flags: it fails with -1 when the calling task does not hold that side, otherwise clears the holder. For port 1 (the console), when both sides are free it calls the console restore routine at `0x118624` with the read descriptor and sets both descriptors to -1; no `close` is made on 0 and 1. For other kinds it calls `close` on the read descriptor and then on the write descriptor, each only when its side was just released, and sets that descriptor to -1. Returns 0 or -1. Established.
- **`uartRead`** (`0x117d60`, 724 bytes). Arguments: record, buffer, length. A length of zero or less returns 0. It builds a 32-word descriptor set containing only the read descriptor and calls `select` on it with no timeout (blocking). A `select` that fails with `EINTR` is logged to the NVRAM log (`UART port %d (%d) select EINTR`) and retried from the top; any other `select` failure is logged and ends the read with the error. Then it calls `read`. On failure `EINTR` (4) and 35 (`EDEADLK` in the published header) are logged and the `read` is retried without another `select`; 104 (`ECONNRESET`) skips the log line; any other error is logged, and every error then takes the path below. A negative result calls `uartFlush` on the read side (mask 1) and returns the negated errno; otherwise the byte count is returned. Established. The 1.44.0 build (`0x10f4b8`, 472 bytes) is shorter: it still calls `select` first but logs only the `EDEADLK` case; the other log calls of this routine are absent there.
- **`uartWrite`** (`0x118034`, 148 bytes). A length of zero or less returns 0. Otherwise it calls `write` once on the write descriptor (+0x04) with the whole buffer. A negative result calls `uartFlush` on the write side (mask 2) and returns the negated errno; otherwise the count written, which may be short, is returned without a retry. Established.
- **`uartGetConfig`, `uartSetConfig`** (`0x1180c8`, 64 bytes; `0x118108`, 148 bytes). Copy the 28-byte configuration block (+0x10 to +0x2b) out of or into the record. `uartSetConfig` first rewrites each of the bytes at offsets 0x16, 0x17 and 0x18 of the caller's block (record +0x26, +0x27 and +0x28 after the copy) from 1 to 2 in place, then copies the block in. No driver request is made; the block takes effect only where another routine reads it. The meaning of those three bytes is not read. Established for the copying and the 1-to-2 rewrite.
- **`uartFlush`** (`0x11819c`, 172 bytes). Arguments: record and mask. Picks the write descriptor when mask bit 1 is set, otherwise the read descriptor, and issues request `0x80047502` with the mask as argument. A failure prints `ERROR:  RESET uart port %d failed: %s` to standard error and the routine returns nothing. Established. That mask bit 0 flushes receive data and bit 1 flushes transmit data is inferred from the two call sites (`uartRead` passes 1, `uartWrite` passes 2).
- **`uartSendBreak`** (`0x118248`, 124 bytes). Issues request `0x80047504` with argument 0 on the write descriptor of the record; a failure prints `ERROR:  SEND_BREAK uart port %d failed: %s` to standard error. Established. The routine does not wait or time the break; any duration belongs to the driver.
- **`uartShowStatus`** (`0x1182c4`, 256 bytes). Arguments: port, a label string and an output buffer. Returns -1 when no record exists for the port. Otherwise it formats one table line into the buffer with the field widths `%-5.5s %-7u %-7s %-7s %-5u    %-5u  %-5u  %-7s %-7s %-5u`: the label, the speed (+0x2c), then strings and numbers taken from record offsets +0x3c, +0x98, +0x9c, +0x9e, +0xa0, +0xa4, +0x100 and +0x104. The four string columns come from two helper routines (`0x118478`, `0x11849c`) that ignore their argument and always return the text `Unknown`. So every line shows `Unknown` in those four columns; the numeric columns come from record fields that none of the routines read in this note writes. Returns 0. Established.
- **Console termios setup** (`0x1184c0`, 356 bytes; routine without an exported name, arguments descriptor and speed code). Reads the terminal attributes of the descriptor with `tcgetattr` (a failure prints `ERROR: can't get termios, errno: %d` and returns), saves the 60-byte structure to a global at `0x3260f4` for the restore routine, and sets: input flags with bits `0x17c0` cleared and `0x20` set; output flags with bit 0 set; local flags with bits `0xa` cleared; control flags with bit 31 cleared for descriptors 0 and 1 and set for any other descriptor; control characters at indexes 0 (0), 2 (8), 3 (0xb), 6 (1) and 10 (0) of the control-character array. It then sets the input and output speed to the speed argument and applies the structure with `tcsetattr(fd, 0, ...)` (a failure prints `ERROR: can't set termios, errno: %d`). In the published Linux header for ARM the cleared input bits `0x17c0` are `INLCR`, `IGNCR`, `ICRNL`, `IUCLC`, `IXON` and `IXOFF`, the set bit `0x20` is `ISTRIP`, output bit 0 is `OPOST`, the cleared local bits `0xa` are `ICANON` and `ECHO`, and control bit 31 is `CRTSCTS` (hints; the bit values are read). The routine does not touch the control-flag character-size or parity bits. Established for the values; inferred for the names.
- **Console termios restore** (`0x118624`, 100 bytes; no exported name). Applies the structure saved at `0x3260f4` to the given descriptor with `tcsetattr(fd, 0, ...)`; a failure prints `ERROR: can't set termios, errno; %d.`. Established.

## Console wrapper (`chario.c`)

The console wrapper serialises access to the one console UART with a semaphore.

- **`charioInit`** (`0x246d4`, 124 bytes). Argument: the port number. Logs `charioInit: already initialized!` when a port number is already stored (the store is zero until the first call), creates the semaphore `CHARIO  ` (initial count 1, flag 9) and stores the port number in `0x1ae204`. `main_task` calls it with port 1, so the console is the record that `uartOpen` special-cases, and its `uartInit(1, 2, 0x9600)` call passes port 1, kind 2 and speed 38,400. Established.
- **`charioOpen`** (`0x24750`, 440 bytes). Argument: a non-blocking request. Takes the `CHARIO` semaphore without timeout (a failure is logged as `can't obtain CHARIO semaphore (%d).`, except while the global panic word at `0x1adf4c` equals 1). The open flags are 1 (write only), plus `0x800` (non-blocking) when the argument is nonzero. With no port stored (port 0) it allocates and zeroes a 264-byte record and marks the wrapper open without touching any device; otherwise it calls `uartOpen(port, flags)` and marks the wrapper open when that returns a record. It then releases the semaphore (failure logged unless panicking) and returns the record or null. Established.
- **`charioClose`** (`0x24928`, 308 bytes). Takes the semaphore; with no port stored it frees the dummy record; otherwise, if the wrapper is open, it calls `uartClose(record, 1)`; it clears the open mark, releases the semaphore and returns the `uartClose` result (0 for the dummy). Established.
- **`charioPort`** (`0x24908`, 32 bytes). Returns the stored port number. Established.

## GPIO device, the parts not read in the first pass

- **`l1ioGpioReset`** (`0x116cc0`, 492 bytes). Arguments: a first argument that is not used and a pin descriptor. Returns `-0xc1c` when the descriptor of `/dev/l1io_gpio` is still -1. Otherwise it issues five requests on that descriptor with a two-byte record whose first byte is the descriptor's byte 3: request `0x40046706` with value 0; `0x40046700` with value descriptor byte 6; `0x40046704` with the complement of descriptor byte 5; `0x40046702` with the complement of descriptor byte 4; and `0x80046708` last, whose value byte is not used afterwards. The first failing request's errno is kept and, if any failed, mapped through the error mapper (`0x117300`, as the other GPIO routines do); otherwise 0. Established. `0x40046700` and `0x40046706` are the write and interrupt-set requests of [arm-programs.md](arm-programs.md); the other three are not named there and their meaning is not read. By the order the routine runs them, descriptor bytes 4, 5 and 6 carry a direction or polarity pair and an output level (inferred).
- **`l1ioGpioInt`** (`0x11715c`, 420 bytes). Arguments: a first argument that is passed on as 0, the pin descriptor, a mask record and a byte. Returns `-0xc1c` when the GPIO descriptor is -1. It repeats up to 32 times: read the interrupt status with request `0x80046708` (record byte 0 = descriptor byte 3; the status byte comes back in byte 1); a failed read is logged (`Error reading L1IO GPIO port %s status, %s`, severity 3, source `l1ioGpio.c`, using the port name at descriptor +0xc) and the routine returns the count so far. If the status byte, ANDed with byte 3 of the mask record, is nonzero it calls `ioExpIntHandler(0, descriptor, mask, byte, status)` and adds its result to the count; if it is zero it returns the count. After 32 rounds with bits still set it logs `Recurring interrupt on L1IO GPIO port %s, bits: 0x%02x` and returns the count. Established. What `ioExpIntHandler` does is not read here (an I/O expander service; compare [ip45-io-expanders.md](ip45-io-expanders.md) for the ColdFire side).
- **`l1ioGpioErrorList`** (`0x15b6ac`, 20 bytes; data). Five pointers: `open error`, `copy error`, `invalid port`, `unknown error` and a null end mark. These are the texts the error mapper's three codes (`-0xc1c` to `-0xc1f`) index. Established as data; the index mapping is inferred from the codes, not traced.

## Port-state poll

- **`portPollState`** (`0x296ac`, 168 bytes). Called from the main loop once every 20 passes (about every two seconds, see `main` in [arm-programs.md](arm-programs.md)). If the flag at `0x1a9424` is set it clears it, sets a second flag at `0x1b0b24` and returns, so the poll is deferred by one call. Otherwise, if the second flag is set, it clears it, logs `Polling for missed port interrupts....` into the NVRAM log and calls `portCheckState(slot, 0xff)` for every slot from 0 to `brickNumSlots` minus 1. Established. Who sets the first flag (an interrupt-time marker that a port event may have been lost) is not read; that purpose is inferred from the message.

## Flash access (`flashdrv.c`)

- **flash map routine** (`0x118688`, 1180 bytes; no exported name). Argument: bank 0, 1 or 2. First releases an existing mapping (`munmap`, `close`). Opens bank 0 as `/dev/mtdblock0` and banks 1 and 2 as `/boot/image_A/l1.bin` and `/boot/image_B/l1.bin` (the letter is `0x40` plus the bank number), with flags `0x1042` (read-write, create, synchronous); a failed open is logged as `flash_map_init: can't open %s: %s`. If no MTD character descriptor exists for the bank it opens `/dev/mtd<bank>` (the bank number was taken as the format's argument; the register was not traced) read-write synchronous and issues request `0x80204d01` (the 32-byte MTD device-information request of the published Linux header) into a stack record; a failure is logged as `flash_map_init: can't %s flash info: %s`. It stores a bank base of bank number shifted left by 28 (0, `0x10000000`, `0x20000000`) at `0x326134` indexed by bank, the device size (word at record +8) at `0x326140` indexed by bank and the erase size (word at +0x0c) in one global (`0x326158`), which each call overwrites. For bank 1 it also initialises the image-information record `FI` (`0x3309bc`): word 0 zero, word 1 -1, word 2 `0x10000000`, word 3 `0x20000000`, word 7 a pointer to `0x1ab804`; calls `flash_get_default_image` (`0x119a90`, not read); reads the environment variable `L1_IMAGE_CURRENT` with `strtoul` into `FI` word 4 (a missing variable is logged and leaves the word unchanged; a result of -1 is logged and stays stored; a value other than `0x10000000` and `0x20000000` is logged and the word is cleared to zero); and sets `FI` word 5 to 3, words 6 and 9 to the device size and word 8 to the erase size. Finally it maps the opened file with `mmap` (shared, read-write, offset 0, the size just stored); a failure is logged as `flash_mmap: can't mmap() flash %s: %s`. Established for the sequence and constants; the roles of the `FI` words are inferred from the values (the two image base addresses match the ColdFire-era image A and B positions named in [flash-nvram-and-image-records.md](flash-nvram-and-image-records.md); that agreement is not proven here).
- **`flash_init`** (`0x118b24`, 288 bytes). Returns 0 at once when its done flag (`0x326130`) is set. Otherwise it runs the flash map routine for banks 0, 1 and 2, then, if the semaphore id at `0x1ab828` is still negative, creates a System V semaphore set with key `0x124f0e5`, one semaphore and flags `0x3b6` (create, mode 0666). A failure logs `flash_init: could not initialize flash access semaphore: [%d] %s` and returns -2. Sets the done flag and returns 0. Established. `main_task` calls it with argument 0.

## JTAG scan port (`sn1sc.c`)

- **`JTAG_Init`** (`0x13cbb4`, 468 bytes). If the init flag (`0x3261ec`) is already 1 it logs `JTAG already initalized` (severity 9, line 0x105) and continues. With the debug flag (`0x3261f0`) set it prints `SCAN DEBUG: Initializing scan controller/interface`. It registers the TAP drivers with `jmstr_set_functions(sn1sc_drive_tap, sn1sc_drive_tap_fixed_tms)`, opens `/dev/mem` read-write synchronous (a failure prints `can't open /dev/mem, errno %d` to standard error and exits 1), maps 0x100 bytes of physical `0x10000000` (the FPGA window `jtagport` also maps; failure prints `can't mmap port FPGA GPIO reg, errno %d` and exits 1) into `mbase` (`0x330b10`), and points `dport` (`0x330a80`) at `mbase` + 0x10. It calls `sn1sc_select_port(1, 0)`, then stores four halfwords to `*dport` in this order: `0x0800`, `0x1000`, `0x0800`, `0x0800`. It creates the semaphore `JTAG Lck` (count 1, flag 9) and sets the init flag. Established. What the four halfwords do on the FPGA (bits 11 and 12 of the port register) is not read; they look like a pulse on one line and a level on another, which is inferred from the repeated `0x0800` around `0x1000`. In the 1.44.0 build the routine is at `0x1341a0`, 468 bytes; not compared.
- **`sn1sc_select_port`** (`0x13cd88`, 704 bytes). Arguments: a port word and a byte index. It reads the halfword at `mbase` + 0x0e (low 12 bits), gathers bits 15 to 10 of `*dport` into one byte (bit 15 to bit 0, bit 14 to bit 7, and bits 13, 12, 11 and 10 to bits 6, 5, 4 and 3), copies that byte into the table `port_io` (`0x330a84`) at every index whose bit is set in the 12-bit value, writes 0 to `mbase` + 0x0e, and then composes a new `*dport` value from bits of `port_io[index]`. The rest of the routine, which builds that value and handles the port number, was not read. Located; the first half is established.

## External-interrupt tasks (`extInt.c`)

- **`extIntInit`** (`0x113b10`, 408 bytes). Arguments: a table of line descriptors (an 8-byte entry per line: the line number as a byte at +0, a word at +4) and a line count. A count of zero or a null table selects a built-in table at `0x1ab714` and count 6 instead: lines 2 to 7, each paired with a name pointer (`I2C_A` to `I2C_F`), the name that the poll task prints in its failure message. Stores the count at `0x3258f0`, allocates the line-state array (`calloc(count, 0x44)`; failure logged as `Could not allocate extIntState list (%d bytes)`), and fills each state with its line number (+5), the descriptor's word (+0xc) and a zero poll timeout (+8). A second call logs `external interrupts already initialized: %d`. Established.
- **`extIntRegister`** (`0x113ca8`, 348 bytes). Arguments: line index, two bytes and a handler pointer. A line index at or above the count logs `Attempt to register handler for invalid interrupt line interrupt` and carries on. A line already holding three handlers (byte at +0x38) logs `Too many external interrupt handlers: %d` and carries on. Otherwise it appends the handler to the line's list of 12-byte entries starting at +0x14 (handler pointer, then the two bytes at +8 and +9 of the entry) and increments the count. Established. The two bytes' roles are not read. The handler entry also has a word at +4 that this routine leaves zero; the poll task calls it in preference to the word at +0 when it is nonzero, so a second registration routine (`extIntRegister2`, `0x113e04`, 348 bytes) presumably fills it; that routine was not read.
- **`extIntSetPollTimeout`** (`0x113ff8`, 156 bytes). Stores a timeout (word) into the line state at +8 after the same invalid-index check. Established.
- **`extIntEnable`** (`0x114094`, 220 bytes). For every line that has at least one handler it sets the byte at +4 to 1 and creates a task named by the line's name pointer, running the poll routine at `0x11468c`, passing the line index and the line state and the numbers `0x1000`, 10, 10 and 9 as the remaining creation arguments (their meanings are not read, as for the log task in [arm-programs.md](arm-programs.md)). Established.
- **line poll task** (`0x11468c`, about 1300 bytes; no exported name). Allocates a 30-byte name buffer, formats `/dev/u_irq_eint%d` with the line number (state +5) and opens it read-only (a failure is logged as `extInt open (%s) failed: %s`). Then it loops on `poll` for readability of that descriptor: the timeout is the line's poll timeout when nonzero, otherwise 15,000 ms while the debug-port interrupt flag `L1DbgPortInt` (`0x1b1718`) is set and 3,000 ms when it is clear. A `poll` failure other than `EINTR` is logged (`%s [EINT%d] poll() failed: %s`). A positive result clears the pending byte (+0x3b) and increments the line's interrupt count (+0x40); the loop then walks the handler list (`brickSlot()` is read once per entry). An entry whose word at +4 is nonzero is called as `fn(slot, byte, entry+8, entry+9)` with a fourth byte from earlier in the routine that was not traced; an entry with a zero word at +4 is called through its word at +0 as `fn(slot, entry byte 8, entry byte 9)`; the returns are summed. Established for the device node, the poll timeouts, the logging and the two call shapes; the source of the extra byte is not traced. The nodes `/dev/u_irq_eint<n>` come from the kernel and are not in the cramfs file list (see `devices` there).

## Router frames (`irouter.c`)

A router packet is a 16-byte host-side header followed by the wire frame. The wire frame starts with a halfword length, then fields at wire offsets 8 and 0xc (words), a byte count of arguments at +0x10, a halfword at +0x12, and that many 8-byte argument records starting at +0x14 (each a halfword at +2 and a word at +4). This layout is established from the byte-order routine's accesses; the field names are not read.

- **`IRouterSetFrameByteOrder`** (`0x1080d0`, 716 bytes). Arguments: a packet and the wanted order (1 or 2). The current order sits in the low two bits of the packet's byte 6. If it already equals the wanted order the routine returns. For order 2 it swaps from network to host order (`ntohs`, `ntohl`) the halfword at +0x10, the words at +0x18 and +0x1c, the halfword at +0x22, and the halfword at +2 and the word at +4 of every argument record counted by the byte at +0x20 (records at +0x24, 8 bytes each); then clears bit 0 and sets bit 1 of byte 6. For any other wanted order it converts the same fields with `htons` and `htonl` and clears bit 1 and sets bit 0. Established. That order 1 is wire (network) order and order 2 is host order follows from the conversion routines used (hint); the program's byte-order variable `IRByteOrder` is passed to this routine after every read. The routine is at `0xfdbb0`, 716 bytes, in 1.44.0; bytes not compared.
- **`IRouterReadPacket`** (`0x107a34`, 1132 bytes). Arguments: one this routine does not use, a read function, an argument for it and a result pointer. It reads frames until a complete packet is assembled. Each pass allocates a 0x410-byte buffer (zeroing 0x2c bytes) and calls the read function with its argument, the address of a slot holding the buffer pointer, and the size 0x400, so a frame's wire bytes begin 0x10 bytes into the buffer (inferred from the byte-order routine's offsets and the 0x410 and 0x400 sizes). A read result of zero or less frees any partial packet, sends an error response for it when its byte 0x16 is zero, and returns the error: the result itself when it equals `-0x25c`, `-0x26d` when it is zero, and `-0x264` for any other value. A failed buffer allocation frees the partial packet and returns `-0x25c`. On a good read it converts the frame with the program's `IRByteOrder` and checks the sequence byte at +0x15: bit 7 means first frame and the low seven bits count the frames still to come. With no packet in progress, a frame without bit 7 is dropped and `-0x265` is returned (with a `NOTFF` frame-log entry when frame-error debugging is on). With a packet in progress, a frame whose count is not the previous count minus one frees the partial packet (logging `FR %d` per node when debugging) and returns `-0x266` (`UNEXF` in the frame log). Each stored frame keeps only bit 0 of the low byte of the halfword at +4 and clears its high byte. The loop ends when a frame's count is 1; the head packet's halfword at +4 then has bits 7 to 2 of the low byte cleared and bit 1 set, the packet counter is incremented (`IRouterPacketCount(1)`), and the result pointer receives the head. Returns 0. Established. The meaning of the halfword at +4 (a flag and a fragment marker) is not read.
- **`IRouterWritePacketReliable`** (`0x107eec`, 484 bytes). Arguments: one this routine does not use, a write function, its argument, a packet list and (on the stack) a flag that asks for the list to be freed. For each packet in the list: allocate length + 0x10 bytes (the length is the halfword at +0x10) and copy them, convert the copy to wire order with `IRouterSetFrameByteOrder(copy, 1)`, then call the write function with its argument, the copy plus 0x10 and the length. A result equal to the length frees the copy and moves to the next packet. A shorter or negative result sends an error response (only when the packet's byte 0x16 is zero and the result is negative, code `-0x261`), frees the copy and the list (when the flag is set), and returns `-0x26e` for a zero result or `-0x269` otherwise. A failed allocation frees the list likewise and returns `-0x25c`. After the last packet the list is freed and 0 is returned. Established. It is absent from the 1.44.0 build's exported names, so that build sends frames by another route (not read).
