# ARM Linux L1: network and flash scripts, MTD tools and the MAC-address helper

The Linux 2.6 packages (`6.5.30:l1#6`, version 1.44.0, and `patches/SG0007149:l1#6`, version 1.48.1) carry shell scripts and small MTD tools around the `l1` program that [arm-programs.md](arm-programs.md) and [arm-linux-packages.md](arm-linux-packages.md) do not read. This note reads them. The start-up script `rc.sysinit` and the `inittab` lines are in [arm-linux-packages.md](arm-linux-packages.md).

**What was read.** Every file named here was extracted from the CramFS of both packages and compared by sha256. Scripts were read in full. The ELF tools (32-bit little-endian ARM, dynamically linked, stripped) were read for their request numbers, strings and flow; routine addresses below are in the 1.48.1 build, and each tool is byte-identical in the two packages unless said otherwise. Grades as in [arm-linux-packages.md](arm-linux-packages.md). Names of Linux request numbers and of the S3C2440 and S3C2410 parts are from published headers and manuals and are hints until a shipped image shows the same name; the numbers and values are read.

## Network link scripts

- **`/etc/ifplugd.action`** (1,819 bytes in both packages; byte-identical). Started by `ifplugd` (an `inittab` line in runlevels 2 to 5) with the interface name and the event. It defines a console-write helper (everything goes to `/dev/console`, because the daemon has no syslog), takes the current runlevel from `runlevel` (the character `#` while init is still starting), and exits 0 without action when the first argument is not `eth0`, printing `WARNING: ifplugd action '%s' for unknown ethernet adapter`. For `down`, `unregister` or `remove` it switches to runlevel 3 (L1 only) when running at runlevel 4, prints `Network link lost, shutting down the L2 Controller.`, and then calls `/etc/ifcfg-eth0` with the event. For `up`, `register` or `add` it calls `/etc/ifcfg-eth0` first; then, unless the kernel command line (`/proc/cmdline`) contains a lone runlevel digit 1 to 6 or `S`, and only when the current runlevel is 3 or `#`, it runs `init 4`, which starts `l2` and `webs`, and in 1.48.1 also `netwatch` (see the `inittab` entries). For `error` and `disabled` it prints `ERROR: ifplugd unexpected action` and exits 0 (the script ends with exit 0 because a nonzero status stops the daemon). So the L2 runs only while eth0 has a link, and a cable pull takes the L2 down within the daemon's polling interval (the polling interval is the daemon's own and was not read). Established.
- **`/etc/ifcfg-eth0`** (2,426 bytes in 1.48.1; 1.44.0 differs only by one comment, sha256 differs). For `down`, `unregister` or `remove` it kills `l2staticip`, `l2dhcps` and `dhcpcd`, deletes the default route on eth0, sets the host name to `localhost`, and sets the interface address to `0.0.0.0` instead of taking the interface down; its comment gives the reason: the interface is not reconfigured properly when a USB Ethernet adapter is used. For `up`, `register` or `add` it runs `/stand/sysco/bin/l2staticip` with all output sent to the console (the comment says the 2.6 kernel needs standard error redirected, or the program panics from within hotplug) and branches on its exit status: 0 skips the DHCP server (`L2 has a static IP address`), 1 skips it (`previous network config errors detected`), 2 starts the DHCP client `/bin/dhcpcd -t 15 -i SGI_L2_CONTROLLER` when that file is executable (15-second timeout, client identifier `SGI_L2_CONTROLLER`) and then `/stand/sysco/bin/l2dhcps`. Then, if `route` shows no default route on eth0, it adds one, and finally sets the host name to the address of eth0 taken from `ifconfig eth0`. Exit status 0 after `up` or `down`, 1 for any other event. Established. The exit-status meanings of `l2staticip` are the script's comment; the program's own side is below.
- **`/etc/hotplug`** (identical in both packages). Hotplug notification script. It exits 0 for any subsystem other than `net`; exits 1 with a console warning when the interface is not `eth0`; otherwise, when `mount` shows a `/work` mount and `/etc/ifcfg-eth0` is executable, it prints `hotplug: <action> eth0` to the console, and with the call to `ifcfg-eth0` commented out does nothing more; otherwise it prints that configuration is delayed until the system is initialised. So eth0 configuration is not done by hotplug in these builds; `ifplugd.action` does it. Established.
- **`/etc/dhcpc/dhcpcd-eth0.exe`** (identical). The DHCP client's address-change hook. It prints `DHCP: new IP address is <arg>` and sets the host name to the address when the host name is still `localhost`. Established.
- **`/etc/rc.shutdown`** (241 bytes, identical). Run by the `inittab` shutdown line in runlevel 6. It prints `Shutting down...`, starts `hwclock --systohc` and `umount -a` in the background with output discarded, and waits for both. Writes the system clock to the real-time clock and unmounts every mounted file system, which includes the three YAFFS flash file systems of `/etc/fstab`. Established.
- **`l2staticip`** (`/stand/sysco/bin/l2staticip`, 7,136 bytes, byte-identical in both packages; version string `l2staticip.c,v 1.6`). Imports `nvramInit` and `nvramGet` from the shared libraries and uses a socket with the interface ioctls `SIOCGIFADDR`, `SIOCSIFFLAGS`, `SIOCSIFADDR`, `SIOCSIFNETMASK`, `SIOCSIFBRDADDR` and `SIOCADDRT` (names as in its error strings), plus `sethostname`. Its output lines are `IP address already configured.` (nothing is changed) and `Configuring IP address from NVRAM:` followed by the address, netmask, broadcast and gateway lines. Read from imports and strings only; the control flow and the NVRAM setting numbers were not read. Inferred.
- **`l2setmac`** (`/stand/sysco/bin/l2setmac`, 8,076 bytes, byte-identical; `inittab`'s `rc.sysinit` runs it when eth0 exists). Main routine `0x8a00`, EEPROM reader `0x8d20` (about 1,700 bytes; both without exported names). Opens a packet socket (domain 17, type 10, protocol `htons(3)`), copies the name `eth0` into a request record and reads the interface's hardware address (request `0x8927`, `SIOCGIFHWADDR`). It then scans the six bytes of that address; if any byte is nonzero it logs `%s MAC address is %02x:%02x:%02x:%02x:%02x:%02x` (severity 6, source `l2setmac.c`) and exits 0 with the address unchanged (the loop at `0x8b18`). Only an all-zero address goes on: the program then calls the EEPROM reader, and when that returns a positive value logs a line that says the address is being set from the EEPROM, and writes the new address with request `0x8924` (`SIOCSIFHWADDR`); failures of either request are logged and exit 1. The EEPROM reader passes the path `/dev/i2c-0` and the address `0x50` to a helper at `0x91c0` (not read), opens the path read-write (`Error: Could not open file %s`) and reads a 256-byte block through a second helper at `0x92bc` that was not read (`Block read failed`; the identification of `0x50` as an I2C slave address is inferred from the helper's name-less call and the path), then treats the block as a board-information record in the shape of the published IPMI platform-management FRU format (hint: the program imports `ipmiCheckCSum`, and its messages say `CH`, a common header, and `BIA`, a board-information area): it checks the zero checksum of the first 8 bytes (`CH BAD CHECKSUM!`), takes the area offset from a header byte times 8 (`BIA MISSING!` when zero), takes the area length from the area's second byte times 8 and rejects more than 200 (`BIA BAD LENGTH!`), checks the area checksum (`BIA BAD CHECKSUM`), and walks the fields from area offset 6, taking each field's length from the low six bits of its type-length byte, stopping at the byte `0xc1` (`END OF OEM FIELDS`) and handling `0xcc` and zero separately (`END OF STANDARD FIELDS`). The diagnostic strings `MAC ADDR is ` and `%2x%2x%2x%2x%2x%2x` show the address is formatted from six bytes of one field. The program's strings show it can also open `/dev/mem` and map memory-controller registers (`can't mmap memctrl regs`); that code was not located in the routines read. Established for the socket and ioctl sequence and the checks and constants named; inferred for the record format; the helpers, the field walk's end and the field that holds the address were not read to the end. The existence of an EEPROM at slave address `0x50` on bus 0 matches the board-record reads of the ColdFire L1 in [mbus.md](mbus.md); that identity is inferred from the shared address only.

## Flash and NAND tools

The cramfs holds five flash partitions as character devices with major 90 (`/dev/mtd0` to `/dev/mtd4` at even minors, with read-only `mtdr0` to `mtdr4` at odd ones) and block devices with major 31 (`mtdblock0` to `mtdblock4`); `/etc/fstab` mounts `mtdblock1`, `mtdblock2` and `mtdblock3` as YAFFS on `/boot/image_A`, `/boot/image_B` and `/work`. Established from the device list and `fstab`.

- **`flasherase`** (`/sbin/flasherase`, 5,728 bytes, entry `0x85d4`, identical in both packages; the string `eraseall 0.1.2`, Arcom Control Systems 2000, names the tool it is built from, a public MTD utility). Takes one MTD device, options `-q`/`--quiet`/`--silent`, `--help`, `--version`. Opens the device and issues the 32-byte device-information request `0x80204d01` (`MEMGETINFO` in the published header; failure prints `unable to get MTD device info`), then erases the device in erase-block steps with request `0x40084d02` (`MEMERASE`: an 8-byte record of start and length) and prints `Erasing %d Kibyte @ %x -- %2d %% complete.` unless quiet; an erase failure prints `MTD Erase failure: %s` and exits. Established for the two request numbers and the messages; the loop's block stepping was read only in outline (inferred). The refresh script below is its only caller in the package.
- **The work-partition refresh script** (installed in `/etc`, name starting `fix`; identical in both packages; it is the only file that calls `flasherase`). A six-command recipe to rebuild the `/work` partition (the comment says it works around corruption of a different journalling file system than the current YAFFS): remove `/tmp/*`, copy `/work/*` to `/tmp`, unmount `/work`, run `flasherase /dev/mtd3`, mount `/work`, copy `/tmp/*` back. `/dev/mtd3` is the partition behind `mtdblock3` (minor 6 of major 90 against minor 3 of major 31; the pairing follows the `fstab` mount of `mtdblock3` on `/work`). The copy is held in RAM (`/tmp` is a RAM file system of 4,192 KiB, see `rc.sysinit`), so a `/work` with more content than that would not fit. Established from the text.
- **`flashload`** (`/sbin/flashload`, 5,556 bytes, entry `0x85a8`, identical). Arguments: an MTD device and a firmware file. It opens both, takes the file size with `stat`, issues `MEMGETINFO` (`0x80204d01`) (`ioctl(MEMGETINFO)` on failure), erases one range with a single `MEMERASE` request (`0x40084d02`; the byte count printed in `Erasing flash (%d bytes)....` is a product of two values, one returned by a helper at `0x89f0` that was not read, so the range's relation to the file size and the erase size is not stated; `done.` follows, or `ERROR!` and `ioctl(MEMERASE)`), then programs the file with `read` and `write` in 512-byte (`0x200`) chunks, padding a short last chunk with `0xff` to 512 bytes before the write. A write that returns another count than 512 prints `ERROR!` and then `flash write error` (negative result) or `flash write error: expected %d bytes, wrote %d`; `%d of %d bytes written to flash` is also a program message, whose condition was not traced. A message when fewer than two arguments: `You must specify a device and the source firmware file`. Established for the request numbers, the 512-byte chunk size and the messages; the chunk loop was read in outline. No file of the package (scripts included) mentions it, so it is run by hand to write a file to a flash device.
- **`nandbadblk`** (`/sbin/nandbadblk`, 4,804 bytes, entry `0x8528`, identical). `main` (`0x861c`) compares its first argument, when there is exactly one, with the string `-s` and passes the result as a flag to one scanning routine (`0x86c4`), which it then calls once for each of `/dev/mtd0`, `/dev/mtd1`, `/dev/mtd2` and `/dev/mtd3`; the arguments never select a partition. The routine opens the device (`open flash` on failure), issues `MEMGETINFO` (`0x80204d01`), and accepts only the geometries it compares (a spare area of `0x10` bytes with `0x200`-byte pages, or one of 8 bytes with `0x100`-byte pages, tests at `0x875c` to `0x8784`; otherwise `Unknown flash (not normal NAND)` and exit 1). For every erase block it then reads the spare area of each of 32 consecutive pages with request `0xc00c4d04` (`MEMREADOOB`; a 12-byte record of page offset, length `0x10` and a buffer; failure prints `ioctl(MEMREADOOB)` and exits 1). It compares byte 5 of the spare data with `0xff` (`0x886c` to `0x8870`). A page whose byte differs sets that page's bit in a 32-bit mask and adds one to a count. Without `-s`, a block with a nonzero mask prints `%-12s  BLK %6d    %08X` (partition name, block number as the block's start offset divided by the erase size, and the mask). With `-s` no block line is printed; a table indexed by the count of marked pages per block is kept, and each non-zero entry for 1 to 32 prints `%-12s %5d blocks w/ %d bad pages`, with the name on the first line of a partition and an empty string after it. Established. That a byte other than `0xff` at spare offset 5 marks a bad page or block is inferred from the tool's name and from the position the public MTD documentation gives the factory bad-block marker for small-page NAND (hint); the code only counts the differing bytes. The meaning of the `-s` flag name is not given by any text in the program.
- **`nandyaffsfix`** (`/sbin/nandyaffsfix`, 4,720 bytes, entry `0x84f4`, identical). Same four partitions, geometry test and page scan as `nandbadblk` (32 pages per block, spare byte 5 against `0xff`, a count and a page mask per block), except that its flag comes from the first argument being `-v` (string at `0x8bbc`) and the flag is inverted: without `-v` the program is in test-only mode and `main` prints `WARNING:   test only, use -v to unerase bad blocks for real!` before scanning. A block is acted on when exactly two of its pages differ from `0xff` or when the mask is exactly 3 (pages 0 and 1 only); every other block is skipped (compares at `0x8880` to `0x8894`). For an acted-on block it prints `Erasing %-12s BLK %5d...` (name, block number) in both modes; in test-only mode it then prints `(test only)`; with `-v` it issues `MEMERASE` (`0x40084d02`, a record of block start and erase size; failure prints `ioctl(MEMERASE)` and exits 1) and prints `done.`. Established. No text or routine in the program says why those two patterns are the criterion or what writes them; that they mark blocks wrongly judged bad is inferred from the tool's name, which ties it to the YAFFS partitions.
- **`nandfix`** (`/sbin/nandfix`, 8,740 bytes, entry `0x8754`, identical). Usage `nandfix [-v] <mtdname> [start addr] [length]`. It opens the device, issues `MEMGETINFO`, accepts only the same two page geometries (compares at `0x89c0` to `0x89e8`), then opens `/dev/mem` and maps 0x100 bytes of physical `0x4e000000` (the NAND controller register window of the S3C2410 family) and 0x100 bytes of physical `0x56000000` (the GPIO window), and reads the word at offset `0xb0` of the GPIO window; unless it equals `0x32440001` it prints `This utility is only needed on S3C2440-based L1 boards.` and exits 0. So the tool acts only when the register at `0x560000b0` (named GSTATUS1 in the manuals, and read as `0x32410000` by `i2cswitch` on the S3C2410 board, see [arm-programs.md](arm-programs.md)) holds `0x32440001`, the S3C2440 identification of the published user manual (hint). That identifies a second processor revision on L1 boards, which this package must also support. It then checks pages (`MEMREAD`, `MEMREADOOB` through the MTD requests), reports `BAD BLOCK (YAFFS)`, `BAD BLOCK (HW)` with a read-back count and `BAD ECCs FOUND IN BLOCK`, and with `-v` rewrites a block with bad error-correction codes: erase (`MEMERASE`), save and restore the out-of-band layout (`MEMGETOOBSEL` and `MEMSETOOBSEL`), write the page and its out-of-band bytes (`MEMWRITE`, `MEMWRITEOOB`). Without `-v` it prints `WARNING:  test only, use -v to fix NAND errors for real!`. Established for the mappings, the identification test and the repair sequence; the ECC arithmetic and the per-page comparison were not read.
- **`nandfixall`** (`/sbin/nandfixall`, 2,907-byte shell script, identical). Runs `nandfix` over `/dev/mtd1`, `/dev/mtd2` and `/dev/mtd3` (the three YAFFS partitions). Because the file systems must be idle, a call from runlevel 3 or higher first re-runs itself in a new session (`setsid`) with its output in `/tmp/nandfixall.out`, drops to runlevel 2 with `init 2`, waits 3 seconds and kills `l1` and `l2`. Without `-v` it only announces a test run. With `-v` it writes 1 to `/proc/sys/dev/mtd/nand/allow_badblock_erase` before the three runs and 0 afterwards (a kernel switch of this system's MTD driver; its kernel side is not in the package files), and finally restores the saved runlevel with `init`. The unmount commands are commented out, with a comment that the file descriptors inherited from `l1` would make the unmount fail. Established from the text.
