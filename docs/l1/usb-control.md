# Origin 300 L1 1.44.0 management USB control path

The selected Origin 300 L1 image implements a USB device function with one declared interface and two bulk endpoints. Its standard control dispatcher does not construct replies for every request number it recognizes. These are selected-image software facts. No Origin 300 USB-host enumeration or L2 transfer was used, so the actual device-controller part, connected host, and host-visible responses remain unknown.

Its selected 982,412-byte range starts at composite offset `0xefdd0`, SHA-256 `0c969f9e98c73826495dc37bff685b3403e248993ba92194a288333d9d42b2f4`. The ColdFire program body has SHA-256 `9db44f3bb06ec90475035781766e1ca7e924f15a0ed215cf855c1f491275fdd1` and loads at `0xffe00000`. Its listing hashes to `7053bb92b2a82508786c957cf822ead2ceea9f50388bf6b44c23767b6589bc5f` and its C-like output to `fa4071f8794f5928d594e8538e97b7fb5e89bc3ee0726f9b4c2c67fa26aa86eb`. The addresses below refer to the first bank unless stated otherwise. The partially relocated bank at addresses `0xffed...`/`0xffee...` has corresponding control and controller functions. Its bodies are **not byte-identical** to the first bank as a whole. Some lower callback bodies match, while absolute references and other instructions differ. This reading does not prove which bank runs on a given unit.

All 4,234 listing rows matched their body bytes. Their request and setup-loop claims below were therefore read from instruction branches and calls, not from recovered C-like text. This byte check does not establish runtime behavior or close the image's unrelated unclassified spans.

## Declared function and setup handling

The device table declares USB 1.00, a 64-byte control endpoint and one configuration. The configuration tree declares interface zero, alternate zero, bulk OUT endpoint 1, bulk IN endpoint 2, and 64-byte maximum packets on both. Its attributes byte is `0x60`: self-powered and remote-wakeup bits set, bit 7 clear. The original [USB 1.0 configuration descriptor table](https://ethw-images.s3.us-east-va.perf.cloud.ovh.us/ieee/4/44/USB_1.0_Specification.pdf) on PDF index page 183 defines those three bits. Under that revision, the image declares a self-powered, remote-wakeup-capable configuration without bus power. The later USB 1.1 reserved-bit rule differs, as the National Semiconductor guide records. This declaration does not predict a later host's acceptance. The descriptor tables sit at `0xffe6fd20` and `0xffe6fd32`. Their mirror tables at `0xffedfd20` and `0xffedfd32` are byte-identical for these 18 and 32 bytes, though the surrounding control code is not. No vendor or product ID, string bytes or firmware internal name is reproduced here.

The control task opens an endpoint-zero function once, then repeatedly requests a setup stage with a 64-byte lower-layer buffer and expects exactly eight setup bytes (`0xffe6fb6c`–`0xffe6fd1e`). It swaps the three 16-bit setup fields from USB byte order before dispatch and selects the read or write branch using the direction bit in the first setup byte. The visible dispatchers do not generally validate its type field, reserved bits, recipient, index or advertised length. A lower controller may reject a transfer before this dispatcher sees it. A short setup read, a reset-like indication, or a failed stage goes through the task's recovery call and returns to the setup loop. If the initial control-function open fails, that task invocation ends instead of pretending an endpoint exists (`0xffe6fbac`–`0xffe6fd16`).

The descriptor send helper splits data into at most 64-byte stages, alternating the lower layer's two IN data-stage selectors (`0xffe6f644`–`0xffe6f6c8`). It clips data to the advertised length. If it sends an exact 64-byte final chunk while the host asked for more than the descriptor supplies, its next iteration requests a zero-length stage. A short, negative or otherwise mismatched lower-layer result makes the helper fail. The dispatcher then uses a generic status-out action, whose lower-layer result must be zero. A nonzero result is an error (`0xffe6fa78`–`0xffe6fb6c`). The write dispatcher similarly expects a zero result for status-in. The setup task follows a failed dispatcher with a lower-layer control recovery action and tries another setup. This describes calls and error handling, not USB transaction timing on a wire.

The configuration-one branch passes zero to the lower configuration routine. It sets the top-level state to configured (`2`) and writes software state `1` to both bulk endpoints (`0xffe6e5cc`–`0xffe6e6c8`). The image's endpoint-status formatter calls state `1` stalled and state `2` active (`0xffe6dea0`–`0xffe6dee0`). The selected-image receive task opens both directions and waits for state `2` before declaring the USB router route open (`0xffe2d1c4`–`0xffe2d23e`, `0xffe6dd64`–`0xffe6dea0`). A successful `CLEAR_FEATURE(ENDPOINT_HALT)` on each matching endpoint can issue lower actions and set that endpoint to state `2` (`0xffe6dce0`–`0xffe6dd64`, `0xffe6f1fc`–`0xffe6f37e`). Other interrupt or host sequences may also affect these states. It does not prove that an L2 host performed those requests, that bulk transfer became usable, or that the state persisted indefinitely. An L2-side setup sequence and first bulk transfer would discriminate them.

## Lower controller, reset and interrupts

The image probes an eight-bit revision at controller-base offset `0x18` and writes/reads even test values through eight-bit offset `0x1b` (`0xffe70968`–`0xffe70a98`). Values with high nibble one pass the revision pattern. Three low-nibble values are quiet, others warn, and a failed scratch comparison returns an error. The selected image then installs reset, control, read and write callbacks, creates their higher-priority deferred interrupt work and a timer, registers a low-level interrupt path, resets the function and starts its control task (`0xffe70a98`–`0xffe70ae0`, `0xffe6e818`–`0xffe6eab8`). The probe matches the prior family inference, but it does not identify the fitted IP45 chip or revision.

The controller callback is a software operation switch. Reset clears address and endpoint state, sets control endpoint state, selects each of eight logical endpoints, and writes per-endpoint byte registers (`0xffe70ae0`–`0xffe70b98`, callback `0xffe71454`–`0xffe7156a`). Configuration zero/one changes endpoint-one/two FIFO and state bytes (`0xffe70bd0`–`0xffe70c50`). An interrupt callback reads byte status and enable registers at offsets `0x12`, `0x14` and `0x16`, dispatches reset/control/read/write paths, clears pending bits and counts repeated inactive interrupts (`0xffe7156c`–`0xffe716de`). Shared ColdFire interrupt mask/enable access elsewhere in initialization uses a 16-bit register at controller-parent base offset `0x36` (`0xffe6e818`–`0xffe6eab8`). These are firmware access widths and offsets only.

A reset or disconnect request invokes the controller reset callback, clears address/configuration state and endpoint states, and wakes control/read/write work with an error (`0xffe6e6c8`–`0xffe6e7d0`, `0xffe70ae0`–`0xffe70b98`). A periodic timer polls the controller and can schedule another reset when its lower-level check fails (`0xffe6eb44`–`0xffe6ecae`). The control task's failed-setup recovery tries a lower reset action and continues its setup loop without recreating the already-open control function.
