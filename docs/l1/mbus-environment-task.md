# Origin 300 L1 M-Bus environmental task trace

The selected L1 1.44.0 first-bank program connects its on-chip M-Bus engine to board identity loading and environmental monitoring. Identity bytes are loaded into controller RAM before the general request endpoint starts. Task-6 request `0x0006` constructs a reply from that RAM copy. Environmental workers make live monitor and expander accesses and can attempt to send state-transition events from task 4. Neither a constructed negative reply nor an event send attempt identifies a fitted part or an electrical failure.

## Evidence and scope

Its selected 982,412-byte package at offset `0xefdd0` has SHA-256 `0c969f9e98c73826495dc37bff685b3403e248993ba92194a288333d9d42b2f4`. All `0xffe...` addresses below locate the selected first-bank program.


## M-Bus engine and transaction result

The first-bank setup at `0xffe6caa8–0xffe6cb46` writes the MCF5206e M-Bus registers as byte accesses at `MBAR+0x1e0` (own address), `+0x1e4` (divider), `+0x1e8` (control), `+0x1ec` (status) and `+0x1f0` (data). It clears control, sets divider `0x13`, clears the own address and enables the block with control `0x80`. Manual Table 13-2, printed page 13-7, assigns divider 480 to `0x13`. The errata says the M-Bus clock is the processor clock divided by this divider. No measured IP45 L1 processor clock is in this evidence. The SCL rate in hertz is unknown. The reset helper makes up to 1,000 status checks after attempting to clear busy. It logs a final failure but does not return a proof that the external bus became free.

Before a transfer, the serialized bus-selector path at `0xffe6c8d4–0xffe6ca26` takes a software lock, calls the board's selector where needed and releases the lock after completion. A selector error aborts before starting the transfer. The low-level call at `0xffe6cc70–0xffe6cd96` polls status bit `0x20` for bus free, with a 1,000-read bound. On exhaustion it invokes reset and returns an error. When free, it clears status, writes control `0xf0` to enter enabled, interrupt-enabled master transmit mode, and writes one supplied 8-bit address byte. Its suspended caller has timeout argument `requested-count + 10`. On a nonzero completion result, it resets the controller before returning the error. These loops and that timeout are not complete transaction retries.

The interrupt continuation at `0xffe6cfac–0xffe6d23e` checks the manual's byte-wide status fields: MCF bit `0x80` for transfer completion, MBB bit `0x20` for bus busy, MAL bit `0x10` for arbitration loss, MIF bit `0x02` for a pending M-Bus interrupt and RXAK bit `0x01` for no received ACK (manual printed pages 13-9–13-10). A receive-byte state disregards RXAK because the master controls its own acknowledge there. Its state steps are address, register or offset byte, following write bytes, repeated START for a read, receive-address byte, receive mode, then read bytes. A read uses control `0xf4` for the repeated START, sends the address with bit 0 set, switches to `0xe0` to receive and performs a data read before useful receive bytes. It writes `0xe8` before the final receive byte to send no ACK, then `0x80` for STOP. The first send of a pure read also ORs bit 0 into the supplied address. A missing ACK, arbitration loss and no transfer-complete condition take distinct result paths. The helper does not issue a second START after such a result. The board selector is deselected and the software lock released at the higher wrapper (`0xffe6cdc0–0xffe6cefc`). Whether an environmental caller or a later worker wake starts another full transaction must be assessed at that caller, not inferred from the 1,000-read loops.

The M-Bus completion handler is on processor interrupt bit `0x0800` in a separate continuation (`0xffe6d1c8–0xffe6d23e`). The environmental input aggregators have their own high and low registrations at `0xffe6c1a4–0xffe6c25c`, on processor lines 6 and 1 respectively. They wake their workers through semaphores and poll registered callbacks. A callback-free result after 100 signaled wakes temporarily masks the input. Ten empty timed wakes permit re-enabling it (`0xffe6c25c–0xffe6c498`). These counters are software interrupt management, not bus ACK retries or measured electrical debounce intervals.

## IP45 records and environmental readers

The IP45 registration at `0xffe45990–0xffe45af0` installs 17 logical expander descriptions, six identity-record routes, three logical monitor descriptions, ten supply descriptions, one fan-control description, five tachometer descriptions and two temperature descriptions. It registers monitor indices 0–1 with the high interrupt worker and expander indices 0–15 with the low worker. The three monitor routes select bus 0 and even 8-bit wire address forms `0x58`, `0x5a` and `0x5c`. The seven-bit forms are `0x2c`, `0x2d` and `0x2e` (`0xffe45de8–0xffe45e0c`). Temperature records reference indices 0 and 1 (`0xffe45f44–0xffe45f54`). Initialization can iterate all three monitor routes (`0xffe69958–0xffe69998`), so the third logical row must not be equated with a third normal IP45 temperature reader.

The monitor register wrapper at `0xffe681c0–0xffe6865c` and the low-level M-Bus wrappers at `0xffe6ce28–0xffe6cefc` make one-byte register reads and writes. The temperature path at `0xffe5e1bc–0xffe5e218` reads one byte, interprets it as signed and subtracts its configured offset. Tachometer and supply records can use monitor registers or expander bits according to their software descriptor type (`0xffe4a8ec–0xffe4aa10`, `0xffe4bdb0–0xffe4bf78`). A failed byte read propagates a result to the reader. The controller's `env` and `fan` commands can call these live readers.

Task 4 is created after board registration and general endpoint setup on the normal continuing branch (`0xffe10570–0xffe10650`). Its initializer at `0xffe2b94c–0xffe2bd2c` creates three interrupt workers and three monitor workers for power, fan and temperature. A monitoring restart first checks settings and power readiness, then configures those groups in that order (`0xffe2b798–0xffe2b830`, `0xffe291d8–0xffe292b0`). An error across a group sets a configuration-error state and can disable monitoring. This combined state does not map one-to-one to an M-Bus NACK.

The power interrupt worker rechecks an out-of-limit value after task waits of 15 and 35 (`0xffe29814–0xffe29cec`). Fan and temperature interrupt workers attempt five reads, waiting 200 task units between attempts (`0xffe29cec–0xffe2a44a`). On each success they add the sample to a sum and divide by the current attempt number. A failed attempt leaves the last computed value in place. Five attempts therefore do not mean five valid samples. Separate recovery workers wait and sample until a transition back inside limits (`0xffe2a454–0xffe2ab78`). The temperature recovery path requires ten successful readings before its limit decision. Worker wait arguments and sample counts establish software ordering and bounds, not seconds, SCL pulses or a sensor's conversion time.

The event formatter at `0xffe27944–0xffe27e32` constructs a diagnostic integer and an attention text line, then conditionally calls task 4's event sender. The controller's fault-only setting suppresses non-fault send attempts while allowing fault attempts. Supply transition codes have `0x1000` through `0x1400` bases, fan codes `0x2000` through `0x2200`, and temperature codes `0x3000` through `0x3300`, with a descriptor index added. The power-down sequence uses `0x4101` countdown events and `0x4102` ending events (`0xffe28178–0xffe282ba`). Warning/fault state is cached to avoid emitting the same transition on every read. Event generation follows the selected controller state-change path.

## Task 6 identity cache and event routing

On the continuing IP45 startup branch, registration probes memory records 2–5, checks node record 0 in a temporary area and invokes the shared scan over all six records before general requests start (`0xffe451fc–0xffe45346`, `0xffe45990–0xffe45af0`, `0xffe6bc04–0xffe6bcec`). That scan clears and reloads each still-present decoded record from its M-Bus route. IO8 record 1 has no separate explicit probe in this branch. The six routes and their capacity/address convention are detailed in the M-Bus and EEPROM reading. No fitted package count follows from six software routes.

Task-6 `0x0006` (`0xffe12526–0xffe12844`, within the general dispatcher) takes component, area, offset and length. It checks presence, record kind, stored area status and bounds, then returns the remaining byte count and a slice of the decoded RAM area. It does not call the M-Bus reader. An absent or disabled route gives minus 104. An out-of-range area or offset gives minus 105. Nonzero stored area status gives minus 107. In particular, an IO8 first-read failure can leave presence set but the area invalid, so a negative BIA reply need not mean the same thing as a disabled DIMM probe. A controller-side diagnostic can read a selected EEPROM live (`0xffe395f4–0xffe39670`).

Task-6 request `0x1007` stores a host-selected event subchannel, and `0x100a` clears it (`0xffe11e18–0xffe13e6e`). No environmental worker is a task-6 request handler. The stored subchannel selects a route for conditional event delivery attempts when it is set. Registration does not start the M-Bus sampling loop, and code inspection does not establish host receipt.

## Open points and the software routes for each

The image establishes byte-wide M-Bus operations, divider selection, state ordering and software timeout arguments. It does not state the oscillator frequency, the fitted monitor or expander part, the bus wiring, or whether the third monitor route responds. Routes for each, none needing hardware:

- Monitor and expander part: the register offsets the code reads and writes through the monitor wrapper at `0xffe681c0` can be tabulated and compared with the register maps of the candidate parts in [mbus-ds1780-candidate.md](mbus-ds1780-candidate.md); the IRIX-side L1 and environment host objects, whose register names are not in the L1 image, are the second route. Unknown until one table matches.
- Whether the third monitor route can be used: trace every use of monitor index 2 (the table at `0xffe45de8`, the loop at `0xffe69958`) in this image and in the 1.48.1 package of the same layout.
- Processor clock: unknown from this image; the timer and UART divider setup in the reset and boot code is the route (open-questions note). MAME's MCF5206E core documents which register writes set the clock-dependent dividers.
- Sample period and debounce: the wait arguments above are task-clock units; converting them needs the task-clock source, which the timer setup in the boot path would name.
