# Origin 300 L1 1.44.0: USB lower-controller callback trace

The visible L1 USB controller path installs a concrete per-slot callback. The generic control status stages call that callback through a software object. The callback enters register-backed receive and control-IN workers, records pending work and enables endpoint interrupts. `GET_STATUS` control-IN data uses operation eight on endpoint zero. A separate operation `0x10` selects endpoint two for bulk IN writes. This settles the static callback target **only when the revision probe takes the visible path**. It does not settle the result of a status stage at the L1 management type-B connector. The revision-`0x81` path calls a different pointer from RAM whose target is not established here.

## Visible callback installation

Startup attempts software slot zero at ColdFire byte base `0x40000000` when the existing software count is positive, and slot one at `0x60000000` only when that count is two (`0xffe55198`–`0xffe55252`). Each attempt writes a scratch byte at base offset `0x1b` and reads revision offset `0x18`. A read of `0x81` calls the RAM pointer at `0x300006f4`. Another value reaches the visible probe (`0xffe6db6c`–`0xffe6dc08`). The visible probe accepts a high-nibble-one revision, verifies scratch read-back, and only on success initializes the software slot (`0xffe70968`–`0xffe70ae0`).

That initializer installs the controller-operation callback at software slot base plus four, and the interrupt callback separately. Slot bases are `0x300036b4` and `0x3000378c`, 0xd8 bytes apart. The slot also stores its selected byte-register base at plus `0x0c`. The operation callback follows that stored base before touching registers (`0xffe6e818`–`0xffe6eab6`, `0xffe71454`–`0xffe7156a`). Thus the indirect call in the lower read and write helpers can be followed to the visible operation dispatcher for an initialized, non-`0x81` slot. A software count does not prove that either window responds on a fitted board or which window reaches the connector.

## Control stages reach register-backed workers

The setup task asks the lower read helper for selector six and requires exactly eight bytes. The read dispatcher also asks selector six for its generic status-out stage. The write dispatcher asks selector three with zero length for its generic status-in stage. These requests are in `0xffe6fb6c`–`0xffe6fd20`, `0xffe6fa78`–`0xffe6fb60`, and `0xffe6f93e`–`0xffe6fa78`. The lower read helper validates the open object, then calls its installed operation callback with operation eight and waits for software completion (`0xffe6d4c8`–`0xffe6d5f2`). It does not itself publish a status packet.

In the visible callback, operation eight reaches the read worker (`0xffe714f2`–`0xffe714fc`, `0xffe70e78`–`0xffe70f24`). The worker selects endpoint zero at base offset `0x0a`. For selector three it examines the transmit side as well as receive state. For selector six it examines receive state. These decisions read indexed FIFO/status offsets `0x04`, `0x09` and `0x0d`, and may read OUT count/data at `0x06`/`0x05` or clear indexed FIFO state (`0xffe70c50`–`0xffe70e78`). When work cannot complete immediately, the worker records pending state in RAM and enables selected done-interrupt bits at base offset `0x16`. The installed interrupt callback reads reset status `0x12`, endpoint-done status `0x14` and enable `0x16`, services endpoint zero and the bulk endpoints, and clears serviced status in `0x14` (`0xffe7156c`–`0xffe716de`). Completion work later resumes the waiting software task. Neither the callback's immediate return nor that task wakeup proves a USB ACK, a zero-length packet, a stall or a host timeout.

The `GET_STATUS` handler formats two intended bytes from software state, subject to the setup-length clip, and hands them to the lower send helper (`0xffe6f6d0`–`0xffe6f820`). That helper uses selectors four and five through the lower helper at `0xffe6d4c8`, invoking the installed operation-eight callback. Its control-IN branch selects endpoint zero and writes payload bytes at indexed TXDAT offset `0x00` and packet count at TXCNTL offset `0x01` (`0xffe70de8`). It can leave completion pending for the interrupt callback. The separate lower write helper calls operation `0x10` (`0xffe6d7c4`–`0xffe6d8b8`); that path selects endpoint two for bulk IN (`0xffe71240`–`0xffe713b0`). It is not the `GET_STATUS` path. These are device-controller intentions.

The visible reset operation zero reaches a routine that clears USB address at `0x10`, global and endpoint status, selects all eight internal endpoint pairs through `0x0a`, initializes indexed endpoint control/FIFOs, and then enables endpoint-zero interrupts (`0xffe70ae0`–`0xffe70b98`). The initializer also registers distinct slot interrupt handlers and unmasks a 16-bit parent ColdFire interrupt bit after reset. That parent write is not a USB byte register (`0xffe6e818`–`0xffe6eab6`). The firmware declares only EP0, bulk OUT 1 and bulk IN 2 in its USB descriptors.

Its B/C/D revision bytes `0x10`/`0x11`/`0x13` match the quiet probe values.
