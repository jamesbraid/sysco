# ARM Linux L1: the helper programs and the L1 program's start-up

The two Linux L1 packages of each set (see [arm-linux-packages.md](arm-linux-packages.md)) carry a small set of command-line helpers beside the main `l1` program. This note reads them. The helpers drive the Samsung S3C2410-family processor's registers through `/dev/mem`, or talk to the board's FPGA through character devices that a kernel driver supplies.

**What was read.** The programs of the 1.48.1 Linux 2.6 package (`patches/SG0007149:l1#6`, 32-bit little-endian ARM executables, dynamically linked, stripped) were read instruction by instruction. The `l1` program there is 1,976,140 bytes (sha256 `61274890f8ba1708b1380a8716e90060d48c22b2505eebf27255744123cdf96e`) and still exports its routine names in the dynamic symbol table, so `l1` routines carry their exported names. Helper routines are unnamed; they are written `sub_<address>` or described by role. Addresses are virtual addresses in the named executable. Where a helper is byte-identical in the other three packages, the entry says so (compared by sha256 of the extracted files). Where it differs, the entry says whether the difference was read.

**Grades** as in [arm-linux-packages.md](arm-linux-packages.md). Register names below are the Samsung S3C2410 user manual's names for the addresses the code uses. That identification comes from published sources (the Linux 2.6.15 `regs-gpio.h` and `regs-spi.h` headers for the S3C2410 and the processor's data book) and is a hint until a shipped image shows the same name; the addresses, widths and values are read from the instructions.

**Decoder note.** The listings were made with a Python ARM decoder. Instructions for the old floating-point coprocessor (coprocessor 1) in `resetmon` decode as nonsense; the entry for that program says which parts rest on the surrounding integer code and the message text.

## Processor register accesses by the helpers

All of these open `/dev/mem` with flags `0x1002` (read-write, synchronous) and map it shared, read-write.

| Helper | Physical window mapped | Length | Registers used (offset from the window) |
| --- | --- | --- | --- |
| `clkset` | `0x56000000` | 0x1000 | `+0x70` GPHCON, `+0x80` MISCCR, `+0x84` DCLKCON |
| `i2cswitch` | `0x56000000` | 0x1000 | `+0x20` GPCCON, `+0x24` GPCDAT, `+0x28` GPCUP, `+0xb0` GSTATUS1 |
| `spiload` | `0x59000000`, `0x56000000` | 0x50, 0x100 | SPI channel 0 `+0x0` to `+0x10`; GPEDAT `+0x44`, MISCCR `+0x80`, GSTATUS1 `+0xb0` |
| `jtagport` | `0x10000000` | 0x100 | halfword at `+0xe` (the board FPGA's JTAG-port select) |
| `resetmon` | `0x56000000` | 0x1000 | `+0x54` GPFDAT, `+0xb0` GSTATUS1 |
| `rdmem`, `wrmem` and the 8- and 16-bit variants | the 64 KiB-aligned base of the address argument | 0x1000 | the addressed word, halfword or byte |

## Entries

### watchdogd

- **`main`** (`/stand/sysco/bin/watchdogd`, 1.48.1 Linux 2.6, `0x89a8`, 624 bytes). Takes the program name (argv[0]) as the prefix of its error messages. Sets signal 12 (SIGUSR2) to the handler below, after first reading the old action of signal 12 into a scratch structure. Opens `/dev/watchdog` read-write; failure prints the open error through the library's error-text helper and exits 1. With exactly one argument equal to `-init` it asks the driver for a status word (ioctl request `0x80045702` with a pointer to a stack integer); an ioctl failure exits 2, and if bit `0x20` of the word is set it runs `/bin/echo watchdog /var/run/softreset` through `system` (a plain echo with no redirection, so it only prints that text), then closes and exits 0. Without `-init` it writes the integer 30 through the same request number (the error text calls it "setting watchdog timeout"; exit 2 on failure), lowers its nice value to -10 with `setpriority` (a failure only prints), and then loops forever: write one byte (the byte at `.rodata` `0x8e44`, value 0) to the watchdog device and sleep 10 seconds. The ten-second period against the 30 in the ioctl is a reading of the code; the driver's use of that number is not in this package. Established. One request number serves both the status read of `-init` and the 30 of the normal path; whether the kernel driver treats the second as a timeout is unknown (the kernel was not read here).
- **SIGUSR2 handler** (`0x8984`, 40 bytes). Prints the line `watchdogd: received SIGUSR2!  hanging...` and spins in an infinite branch to itself, so the daemon stops feeding the watchdog and the board resets when the driver's timer expires. A deliberate way to test the reset path. Established.
- Context: `/etc/inittab` starts `watchdogd` with no argument under `respawn` in runlevels 1 to 5. No file of the package (scripts included) passes `-init`; the extracted regular files were searched for `watchdogd` and `softreset`, and only `inittab` and the `l1` binary (which holds the strings `softreset` and `softrst`) mention them. Established as absence from the packaged files. The legacy 2.4 `watchdogd` (sha256 differs; read in outline at `0x8974`, 396 bytes) has the same open, `-init` status check and echo, and the same SIGUSR2 spin, but no timeout ioctl and no `setpriority`; its feed loop writes one byte and sleeps 10 seconds in the same way. Inferred (outline only).

### clkset

- **`main`** (`/stand/sysco/bin/clkset`, `0x8874`, 1084 bytes; usage routine `0x8848`, 48 bytes). Byte-identical in all four packages. Usage text `usage: %s 0|1 m|u|f|h|p|d [p|u]`; wrong argument counts, an index outside 0 to 1, or an unknown selector call usage, which exits 1. The argument count must be 3 or 4. Argument 1 selects output pin 0 or 1. Argument 2 is either `on`/`off` or a source selector; only its first character is tested, so `mpll` acts as `m`.
  - `on` / `off`: clears the two GPHCON bits at position 18 + 2n and sets them to 2 for `on` or 1 for `off`, then exits 0. Pin 0 is GPH9 and pin 1 is GPH10; in the published S3C2410 header, 2 selects the clock-output function (`CLKOUT0`, `CLKOUT1`) and 1 selects plain output.
  - A selector letter: `m` 0, `u` 1, `f` 2, `h` 3, `p` 4, `d` 5, stored in MISCCR bits 6:4 for output 0 (bits 10:8 for output 1) after clearing the old field. In the published header those values name the MPLL, UPLL, FCLK, HCLK, PCLK and DCLK sources. The letters come from a jump table of 18 words at `0x89d4` indexed by the character minus `d`; entries not named above point at the usage call.
  - With selector `d`, a fourth argument `p` or `u` is required (0 or 1; any other first character calls usage; the routine reads `argv[3]` without testing the argument count, so `d` with only three arguments dereferences a null pointer); the routine then also rewrites DCLKCON, whose low half is replaced for output 0 and whose high half for output 1, with `(flag << 1) | 0x11`. The routine reaches that DCLKCON write for every selector letter, not only `d`; for the other letters the flag word is a stack slot that no earlier instruction sets (the stores to it are at `0x8a98` and `0x8aa4`, both on the `d` path). Established from the instructions. What those DCLKCON bits mean is a hint from the processor data book, not read in an image.

### i2cswitch

- **`main`** (`/stand/sysco/bin/i2cswitch`, 1.48.1 Linux 2.6 `0x88a4`, 684 bytes; usage `0x8848`, 96 bytes). Needs exactly one argument or prints usage and exits 1. Opens `/dev/mem`, maps the processor's GPIO block, and computes one value from the first character of the argument, then stores that value as a word at GPCDAT (`+0x24`) and prints `GPCCON=0x%08x GPCDAT=0x%08x GPCUP=0x%08x` read back from `+0x20`, `+0x24` and `+0x28`. Which table applies depends on two things:
  - If the environment variable `L1_P0_HW` is set: characters `0` to `3` give the value 0 to 3; any other first character gives 4 (the usage text for this case is `0|1|2|3|i`).
  - Otherwise, if GSTATUS1 (`+0xb0`) reads `0x32410000` (the S3C2410 identification in the published header): `0` to `7` give `0x10 | n`, `8` gives 8, `m` gives `0x18`. Any other character leaves the value at -1 and prints usage. If GSTATUS1 holds anything else, the argument is parsed with `atoi`: 0 to 7 give `0x10 | n`, 8 to 15 give `8 | (n & 7)`, and anything else prints usage.
  The value drives the low five port C pins. That these pins select an I2C bus segment is an inference from the program's name and from the I2C helpers' use of the bus; no routine of this program touches an I2C device. The 2.4 packages carry a different build (`sub_8878`, 544 bytes; sha256 differs) which was not compared line by line. Established for the 2.6 program; inferred for the pin purpose.

### i2cspeed

- **`main`** (`/stand/sysco/bin/i2cspeed`, `0x88ac`, 1056 bytes; usage `0x887c`, 52 bytes). Byte-identical in all four packages. Argument count 2 or 3. It tries to open `/dev/i2c-0`, then `/dev/i2c0`, then `/dev/i2c/0` (flags 2); if all three fail it prints one message naming the three paths and the error, exits 1, and adds `Run as root?` when an error was permission denied (13). With two arguments it takes `atoi(argv[1])` and issues ioctl `0x780` with that value: the usage text names it a speed in kHz for the 2.6 kernel. With three arguments, the first is a selector and the second a divider: if the selector is 16, 100 is added to the divider; the sum goes to the same ioctl `0x780`. The usage text names this form for the old Linux 2.4 kernel (divider for PCLK, with 16 or 512 as the selector). After either form (and with one argument or none beyond the program name, where it only reads) it issues ioctl `0x781` with a pointer to an integer and prints `I2C clock speed %d KHz`. Failed ioctls print an error and exit 1. Requests `0x780` and `0x781` are not in the published Linux i2c-dev header; they belong to the L1 kernels' own I2C driver, whose code is not read here. Established for the program flow; the request meanings are inferred from the usage and error text.

### jtagport

- **`main`** (`/stand/sysco/bin/jtagport`, `0x8848`, 396 bytes; usage `0x8814`, 56 bytes). Byte-identical in all four packages. Needs exactly one argument; `atoi` of it must be 0 to 6, otherwise it prints `invalid JTAG port %d specified, valid ports are 0-4` but does not exit and carries on with the value. The usage text says 0 to 6 and the error text says 0 to 4, and the check accepts 0 to 6; the code is the same in all four packages. It prints `Configuring FPGA JTAG master to use port %d.`, maps 0x100 bytes of `/dev/mem` at physical `0x10000000`, and stores one halfword at offset `0xe`: `(port << 12) | (1 << port)`. Nothing is read back and nothing waits. The L1's board FPGA uses this window (see `l1ioInit` below, which maps the same address). Established.

### spiload

- **`main`** (`/stand/sysco/bin/spiload`, 1.48.1 Linux 2.6 `0x8a90`, 1412 bytes) with the bit reverser (`0x89b4`, 136 bytes) and a status printer (`0x8a38`, 92 bytes). Loads an FPGA configuration file through SPI channel 0. Needs one argument, whose last three characters must be `bit` or `rbf` (the file is opened with mode `r`; a name of two characters or fewer, or any other ending, prints the "not very smart" text and exits 1).
  - A `.bit` file (Xilinx): runs the shared header reader (`initbh`, `readhead`; they live in `libscan` and are not read here) and prints the creation date and time, the design name, the part name and the stream length it returns; a header failure prints that the file is not a valid Xilinx bitstream and exits 2. The data bytes are then sent as read.
  - A `.rbf` file (Altera): each byte is sent bit-reversed (swap of nibbles, bit pairs and bits, done with masks `0xaa/0x55`, `0xcc/0x33`, `0xf0/0x0f` in `0x89b4`), which matches a least-significant-bit-first stream. Inferred from the reversal alone.
  - Hardware sequence. Maps the SPI channel 0 registers (`0x59000000`, 0x50 bytes) and the GPIO block (`0x56000000`, 0x100 bytes) and prints a status line `INITIAL`. Then reads GPEDAT, writes it with bit 0 cleared, waits 10 microseconds, writes it with bit 0 set, waits 10 microseconds, and prints `AFTER PROG CLEAR`. The status line prints GPEDAT bit 1 as `DONE/CONF_DONE` and bit 2 as `nINIT/nSTATUS`. It then writes SPCON0 = `0x18`, SPPIN0 (`+0x8`) = 3 and SPPRE0 (`+0xc`) = 0. For each byte of the file: write SPTDAT0 (`+0x10`), spin until SPSTA0 (`+0x4`) bit 0 is set, then if SPSTA0 has any of the bits `0x60` set print `SPI ERR 0x%02x` and exit 3, then if GPEDAT bit 2 is clear print `INIT LOW! (bcnt=%d)` and exit 3. (A second flag that would skip that last test is initialised to zero and never changed, so the test always runs.) After the last byte it prints `write %d bytes`, waits 10 microseconds, prints `FINAL`, and if GSTATUS1 reads `0x32410000` it clears MISCCR bit 16, waits 10 milliseconds and sets it again, printing `toggle RSTOUT...`. It never waits for or tests the done line. Established. The names of the SPCON, SPSTA, SPPIN and GPEDAT bits come from the published S3C2410 header; in that header SPSTA's error bits are 2 and 1, not the `0x60` the program tests, so which condition `0x60` stands for is unknown here (the same mask appears in the `l1` loader below). The 2.4 build of `spiload` differs only by a 1356-byte `main` against this 1408-byte one; the difference was not read.

### rdmem, rdmem8, rdmem16

- **`main`** (`/stand/sysco/bin/rdmem` `0x8874`, 492 bytes; `rdmem8` 488 bytes; `rdmem16` 504 bytes; each with a usage routine at `0x8848`, 48 bytes). Present only in the 1.48.1 Linux 2.6 package. One or two arguments after the program name: an address (parsed with `strtoul`, base detected) and an optional count of units, default 1 (`atoi`). Opens `/dev/mem` (a failure prints the errno and exits 1) and maps 0x1000 bytes at the address with its low 16 bits cleared. Then prints one line `0x%08x = 0x%08x` per unit: the unit's address, advancing by 4, 1 or 2 bytes, and the word, byte (`0x%02x`) or halfword (`0x%04x`) read from the mapping at the address's low 16 bits plus the unit offset. The access is a plain load of the unit's width. Only the low 4 KiB above the 64 KiB boundary is mapped, so an address whose low 16 bits reach 0x1000 or more, or a count that runs past it, reads outside the mapping. Established. The three programs differ in the width of the load, the step and the print format.

### wrmem, wrmem8, wrmem16

- **`main`** (`/stand/sysco/bin/wrmem` `0x8844`, 432 bytes; `wrmem8` 440 bytes; `wrmem16` 460 bytes). Present only in the 1.48.1 Linux 2.6 package. Exactly two arguments (otherwise usage, exit 1): an address and a value, both `strtoul`. Maps `/dev/mem` as `rdmem` does, then stores the value: `wrmem` as a word at the address rounded down to 4 bytes, `wrmem16` as a halfword at the address rounded down to 2, `wrmem8` as a byte at the exact address (the value is first reduced to its low 16 bits in the 8-bit and 16-bit versions; the store keeps the low 8 or 16). It then reads the unit back and prints the original address and the read-back value: `0x%08x = 0x%08x` for the word version and `0x%08x = 0x%04x` for the other two (so `wrmem8` prints a byte in a four-digit field). Established.

## Reset button monitor

### resetmon

- **`main`** (`/stand/sysco/bin/resetmon`, 1.48.1 `0x89ec`, 1872 bytes) and **the press-sequence handler** (`0x8f3c`, 216 bytes; the log helper it calls, `0x8ed0`, was not read). Present in both 2.6 packages and absent from the legacy ones; the 1.44.0 and 1.48.1 builds differ in bytes and have the same strings. `/etc/inittab` enables it only in 1.48.1 (the 1.44.0 inittab has the line commented out). It maps the processor GPIO block, reads GSTATUS1 (`+0xb0`) and, if the word is not `0x32440001`, sleeps in a loop for ever. That value is the Samsung S3C2440A identification in the data book (hint); the S3C2410 board value the helpers above test is `0x32410000`, so this program is meant for boards whose processor reports the 2440 identification. Otherwise it reads the button as the inverse of GPFDAT bit 6 (so a low pin is a press; pin F6 is the external interrupt 6 line, a hint from the published header) and warns `L1 reset button appears stuck!` if already pressed. It opens `/dev/u_irq_eint6` (character device 248:50 in the 2.6 packages) and polls it with a 500 ms timeout while a click sequence is in progress and without a timeout otherwise. After each wake-up it re-reads the pin; each press edge counts one click, and it measures the time since the previous edge with `gettimeofday`. When the pin is released and no further press follows in 500 ms, it calls the handler with the number of clicks and the length of the last press in seconds. Each pass ends with ioctl `0x80047501` (argument 0) on the interrupt device, whose name the program gives as re-enabling the button interrupts (an error prints `Error re-enabling reset button interrupts` and exits 3). Established for the structure; the duration arithmetic uses the old floating-point coprocessor and was read only through its integer scaffolding (inferred).
  - Handler: with one click and a press of at least 5 seconds it logs `L1 reset button: 5+ second press, reboot L1` through `/stand/sysco/bin/l1log "<text>"` and runs `reboot`; with one click and at least 2 seconds it logs the 2+ second message and runs `killall l1 2>/dev/null`; with two clicks it logs the double-click message and runs `killall -USR1 l1` (signal 10; the `l1` program installs `trace_handler` for it, listed below, and its body was not read); more than two clicks, or a single short press, only logs an unrecognised-sequence warning. The 5 and 2 second thresholds are taken from the log messages, since the comparison constants are floating-point immediates in the undecoded coprocessor instructions. Inferred.

## Serial and FPGA UART test helpers

### ulisten

- **`main`** (`/stand/sysco/bin/ulisten`, `0x894c`, 988 bytes; usage `0x88d8`, 120 bytes). The 1.44.0 and 1.48.1 builds differ in bytes; the strings and the routine sizes are the same, and the difference was not read. Arguments: leading words that start with `-`, then one UART number. The loop over leading words accepts only `-ppp` (it stores 1 in a flag that already starts at 1, so PPP mode is always on); any other word starting with `-` is skipped without an error. With no UART number left it prints `uart# (0-15) is required` and the usage line and exits 255; a number outside 0 to 15 prints `invalid uart# specified` and usage. It opens `/dev/l1io_uart<N>` twice, once with flags `0x801` (write-only, non-blocking) and once with `0x800` (read-only, non-blocking), and issues ioctl `0x80047503` with argument `0x400` on each descriptor (the messages call this setting write and read PPP mode; a failure exits 1). Then it loops for ever: `select` on the read descriptor with no timeout, `read` up to 1024 bytes, and print `Pkt received: %d bytes`. A select or read error exits 2. Nodes for UART numbers 0 to 19 are character device 199 with minors 0 to 19, and UART numbers 20 to 31 use minors 80 to 91 (from the filesystem listing). Established. What ioctl `0x80047503` does inside the driver is unknown; its role as a PPP framing mode is the program's own wording. The `/dev/l1io_*` driver is not in this package's files.

### uloop

- **`main`** (`/stand/sysco/bin/uloop`, `0x8f2c`, 11,216 bytes in 1.48.1 Linux 2.6; 1.44.0 and the legacy builds differ). A test tool for the FPGA UARTs: it writes a data pattern to one UART and checks it arrives at the same or a second one. Options read from the strings and the compare chain: `-p <min>[,<max>]` starting and ending data patterns, `-l <bytes>` length, `-f`, `-nf`, `-a`, `-ext`, `-ppp`, `-pkt`, `-c`, `-ni`, `-ii`, `-nr`, `-nw`, and one or two UART numbers 0 to 31 (or device names) joined to the prefix `/dev/l1io_`. It prints the test banner, opens a write and a read descriptor, may set loopback mode with ioctl `0x80047501` argument 1 (`can't set loopback mode`) and PPP mode with `0x80047503` argument `0x400`, starts a writer thread with `pthread_create`, and compares what comes back, reporting `data miscompare:  i=%d   exp=%02x   act=%02x`. The pattern names printed by its status line are: incr, decr, 0x55, 0xAA, alt AA/55, alt 55/AA, all 0s, all 1s, alt 00/FF, alt FF/00, walking 0, walking 1, sliding 0, sliding 1, random. It uses the packet library (`IRouterMakePacket`, `IRouterWritePacket`, `IRouterReadPacket`) in `-pkt` mode. Only the option parsing, the device naming and the ioctl calls were read; the pattern generator and the comparison loop were not. Inferred.

### l1log

- **`main`** (`/stand/sysco/bin/l1log`, `0x887c`, 496 bytes; usage `0x8840`, 64 bytes). Present in both 2.6 packages (identical bytes in the two). Exactly one argument, a message. Opens `/dev/l1log` with flags `0x1801` (write-only, non-blocking, append), which is a FIFO in the filesystem (character-device list entry type `fifo`). Waits with `select` for the descriptor to be writable, with a zero timeout structure: if not writable it prints `ERROR: cannot write log message, L1 does not appear to be reading!` and still tries to write. Writes `strlen(message)` bytes with no newline added. Errors exit 1. The FIFO is read by the L1 program's log task (`L1LogInit` below). Established.

### netwatch

- **`netwatch`** (`/stand/sysco/bin/netwatch`, a 2066-byte shell script; 1.48.1 Linux 2.6 only). Started by `inittab` through `/bin/sh` in runlevels 4 and 5. Waits 30 seconds, then every 11 seconds runs `ifconfig eth0`; if the interface is RUNNING and neither the receive nor the transmit packet count has changed since the last pass, it appends a dated warning to `/work/netwatch.log`, runs `tcpdump -c 1 -q` for 5 seconds and logs whether any packet was captured, then takes `eth0` down and back up with its old address and netmask. The script's own comment calls it a workaround for an Ethernet adapter that stops with no error and says the L2 normally sends a packet at least every 5 seconds. Established from the text.

## Network request client

### l1cmd

- **`main`** (`/stand/sysco/bin/l1cmd`, 1.48.1 Linux 2.6 only, `0x8d78`, 2088 bytes). With no argument it calls the usage routine (`usage: %s <l1 command>`, exit 0). Otherwise it joins the arguments with single spaces into a 1024-byte buffer, and connects to `localhost` over TCP on port `IR_PORT_BIAS + 11000` (the bias is the library variable that the L2 daemon also adds to its ports; `0x2ac0 + 0x38` is 11,000). A failed connection prints `can't connection to localhost:<port>` and exits -1. The buffer is then split at semicolons and each piece is sent as one request. For a piece the program calls `IRouterInit(0)`, builds a packet with `IRouterMakePacket` from an address record whose first word is `0x0ffff003` and a zeroed second record, with a descriptor count of 2: the first 8-byte descriptor is all zero (type 0, no payload) and the second has first byte `0x0a` (type 2, a string, with the free-after-copy flag), length the piece's length plus one, and a `strdup` copy of the piece as payload; writes it with `IRouterWritePacket`; waits with `select` on the socket with no timeout; and reads the reply with `IRouterReadPacket`. The descriptor layout is that of the router packet read in [l2/router-packet.md](../l2/router-packet.md), from the L2 build of the same library. Reply handling: if the reply's byte at `+0x13` is `0x13` the program waits for another packet; if it is non-zero otherwise, it prints `ERROR: response error - ` plus the library's error text and exits -1. If the reply has no arguments, or its first argument is not a string, it prints `ERROR: command error - no reason given.` and exits -1, or the argument's text when the first argument is a string and the reply's code is 2. Otherwise it prints every string argument of the reply, then moves on to the next piece; after the last it closes the socket and exits with the close result. Which handler in the L1 program serves destination word `0x0ffff003` was not followed. Established for the program flow; inferred for the packet field meanings (taken from the L2 build of the library, not read in the ARM build).

## Sibling helpers read in outline

- **`cfg_dump`**, **`cfg_snap`**, **`cfg_diff`** (`/stand/sysco/bin/`, 2.6 packages; `cfg_dump` 6156 bytes, `cfg_snap` 6156, `cfg_diff` 10,276 in 1.48.1). Thin front ends for the scan library. All three parse the system-controller command line with `sn1SCParseCmdline`, initialise a node record with `enode_init` and `enode_set_loc`, and use the default file name `default.scf`. `cfg_dump [file]` loads a system configuration file (`scdata_load_from_file`), checks its ports (`scdata_check_ports`) and prints it (`scdata_display`). `cfg_snap [sysco] [file]` loads the current hardware configuration (`scdata_load_from_sysco`), checks the ports and writes the file (`scfile_create_from_scdata`). `cfg_diff file [--l2 L2 | sysco] [-v] [-add n] [-e n]` loads the file and either a second file (labels FILE1 and FILE2) or the hardware (label HARDWARE), compares them (`scdata_compare`), and prints the number of differences; `-add n` raises all rack numbers (`scdata_adjust_rack_numbers`), `-e n` limits the printed errors, `-v` selects verbose output, and an undocumented `-force` is accepted. Version string printed by `cfg_diff`: `1.5`. Established for the call lists and options; the work is in `libscan`, which was not read, so the file format is not described here.
- **`i2cdetect`**, **`i2cdump`**, **`i2cset`** (`/stand/sysco/bin/`, byte-identical in all four packages; 7712, 10,524 and 9148 bytes). Command-line tools of the public lm-sensors family for the Linux i2c-dev interface, reduced to the programs' flows. All three open `/dev/i2c-<bus>`, `/dev/i2c<bus>` or `/dev/i2c/<bus>` (the first that opens), ask the adapter for its functions (ioctl `0x705`), set the slave address (`0x703`, or `0x706` to force it when the address is busy) and use the SMBus ioctl (`0x720`). `i2cdetect [-l] bus` probes every address 0x00 to 0x7f with a quick write, printing `UU` when the kernel says the address is claimed and `XX`, `AL`, `TO` or `??[errno]` for the failure kinds, and with `-l` a counted summary per address; `i2cdump bus addr [b|w|s|i] [bank [bankreg]]` dumps a device in byte, word, SMBus block or I2C block form; `i2cset bus chip data-address value [b|w]` writes a byte or word after a confirmation prompt that warns it may ruin a memory module's serial EEPROM, and reads the value back. The standard i2c-dev request numbers are those of the published Linux header (hint). Inferred from strings, import lists and the ioctl call sites; the main bodies were not read line by line.

## L1 program: start-up and the pieces that reach hardware

All addresses in this section are in `/stand/sysco/bin/l1`, 1.48.1 Linux 2.6 (the 1.44.0 build and the legacy ones were not re-read; they carry the same exported routine names).

- **`main`** (`0x20ec0`, 992 bytes). Saves argv[0]; installs the handler `oops_handler` (`0x20ca4`, 280 bytes) for signals 11, 7 and 6 (segmentation fault, bus error, abort) and `trace_handler` (`0x20dbc`, 260 bytes) for signal 10 (SIGUSR1), seeds the random generator from the clock, and then handles four special arguments: `-env` (opens the NVRAM, prints `TZ=<setting 0x46>`, exits 0; the boot script uses this line to set the environment), `-rs` (opens the NVRAM, prints settings 1 and 2 as `%d.%d`, exits 0), `-bg` (sets a flag passed to the main task) and `-l2host <name>` (stores the host name; missing name prints an error and exits 1). It prints `SGI L1 Controller:  Version 1.48.1`, calls `exceptionInit` (a failure is logged), calls `main_task(bgflag, 0)`, and then loops for ever: sleep 100 ms, drain a line buffer into the NVRAM log (splitting on a separator string and calling `nvramLogInsert` for each piece), and after 20 passes call `portPollState`. Established.
- **`main_task`** (`0x97f8c`, 552 bytes) is the start-up sequence, in this order: `nvramInit`; log `L1 booting 1.48.1` into the NVRAM log (`nvramLogFinsert`); `vramInit`; `exceptionFindResetReason` and log `detected boot type is <name>`; `L1LogInit`; `IRouterInit` with the rack and slot taken from NVRAM settings 1 and 2 (`((setting1 & 0x3ff) << 6) | (setting2 & 0x3f)`); `brickInit` and an optional hook; `l1ioInit(0)`; `uartInit(1, 2, 0x9600)` (third argument 38,400 decimal; read as the line speed, and the first two arguments were not decoded); `charioInit(1)`; `syslogLibInit`; `flash_init(0)`; `JTAG_Init`; `SysComConfig`; a second hook; `bladeInitAllHardware`; `sernumInit`; `exceptionResetReport`; the request, command, loopback, route and event initialisers (`L1ReqInit`, `SMPCmdInit`, `LpbkInit`, `RouteInit`, `EvtInit`); `BkDrInit`; `L1CfgInit`; `SMPInit(bgflag)`; `EnvInit`; `scanpktInit`; `FlashInit`; `extIntEnable`; a third hook; `L1NetInit`; `B2BInit`; `SysComInit`. It then shows the brick on the display: if `brickGetType` is `0x3f` it writes `  UNKNOWN   ` and `BRICK TYPE!!` to the display, otherwise it calls `UtilDspBrick`, shows `L1 running` and, after a soft reset, `L1 rebooted`; finally it records the slot in the slot memory (`vramSlotSet`, slot from `brickSlot`, entry `0x26`, value 1). Established.
- **`l1ioInit`** (`0x971d0`, 3352 bytes). Opens `/dev/mem` (errors logged to syslog), maps the board FPGA's two chip-select windows: physical `0x08000000` (0x200 bytes) and `0x10000000` (0x100 bytes). After a soft L1 restart (`exceptionIsSoftReset`) it first tries to open `/dev/l1io_uart0` read-write and non-blocking (flags `0x802`): if that opens, or fails with any errno other than 19 (no such device), the descriptor is closed and `l1ioInit` returns 0 without loading, taking the FPGA to be configured already; only errno 19 logs `L1IO FPGA: not programmed after soft L1 reboot, reprogramming.` and goes on to load. After a hard reset it always loads. Then it picks a bitstream path from the brick type byte (`brickGetType`) through a table of 90 words at `0x97494` indexed by the type minus `0x24`, and for the type `?` (`0x3f`) from the brick sub-type. The mapping read from that table:

  | Brick type code (character) | Bitstream under `/stand/sysco/bin/` |
  | --- | --- |
  | `0x24` (`$`, the string `ip69`), `0x2c` (`,`, the string `1932`) | `l1io_1932.rbf` |
  | `0x2b` (`+`), `0x4a` (`J`), `0x4b` (`K`) | `l1io_pa.rbf` |
  | `0x2d` (`-`, the string `drouter`) | `l1io_dense_rtr.rbf` |
  | `0x2e` (`.`, the string `191010`) | `l1io_191010.rbf` |
  | `0x40` (`@`, the string `vortix`) | `l1io_vortix.rbf` |
  | `0x42` (`B`, the string `gemini`), `0x46` (`F`) | `l1io_gemini.rbf` |
  | `0x44` (`D`, the string `nl4r`), `0x53` (`S`, the string `nl4s`) | `l1io_nl4r.rbf` |
  | `0x4c` (`L`, the string `dorado`) | `l1io_p0_dorado.rbf` when the sub-type is 7, otherwise `l1io_dorado.rbf` |
  | `0x4d` (`M`) | `l1io_ip67.rbf` |
  | `0x5e` (`^`) | `l1io_sa.rbf` |
  | `0x7b` (`{`, the string `ip71`) | `l1io_ip71.rbf` |
  | `0x7d` (`}`, the string `1955`) | `l1io_1955.rbf` |
  | `0x3f` (`?`, unknown) with sub-type `0x2e` / `0x2d` / `0x40` / `0x7d` | `l1io_191010.rbf` / `l1io_dense_rtr.rbf` / `l1io_vortix.rbf` / `l1io_1955.rbf` |
  | `0x43` (`C`, the string `ip35`), `0x33` (`3`, `ip37`), `0x34` (`4`, `ip45`), `0x35` (`5`, `ip41`), `0x36` (`6`, `twister`), `0x4f` (`O`, `opus`) and every other code | none: `no L1IO FPGA bitstream defined for this brick type!` |

  The loader then opens the file (a failure logs `can't open L1IO FPGA bitstream %s` and returns), requires a name of at least three characters ending `bit` (Xilinx header check through `initbh` and `readhead`; error text `is an invalid Xilinx FPGA bitstream!`) or `rbf`, and runs the same SPI sequence as `spiload`: map `0x59000000` and `0x56000000`, pulse GPEDAT bit 0, set SPCON0 `0x18`, SPPIN0 3 and SPPRE0 0, then per byte write SPTDAT0, wait for SPSTA0 bit 0 and test the `0x60` mask. The `0x60` test logs `SPI TX error during programming!`; a separate test of the done line logs `FPGA CRC error error during programming!`. A failed load is retried: messages `L1IO FPGA load failed, retrying (%d)` and, once a counter passes 2, `L1IO FPGA load failed!`; the exact loop bound was not traced. After the load it pulses MISCCR bit 16 low and high (10 ms apart) when GSTATUS1 reads `0x32410000`, as `spiload` does. Established for the table, the mapped addresses and the sequence shape; the retry details are inferred.

  The string-to-code map is `brickConvertString` (`0x10d7d4`, 1140 bytes): a one-character argument is upper-cased and looked up through its own table, and a longer argument is compared with `ip35`, `ip37`, `ip45`, `ip41`, `twister`, `vortix`, `opus`, `gemini`, `dorado`, `ip69`, `191010`, `1932`, `1955`, `drouter`, `ip71`, `nl4r`, `nl4s` and two more strings that were not read; the codes in the table above are those it returns (the compare chain at `0x10d920` to `0x10dbe0`). So, in this program, `ip35`, `ip37`, `ip45`, `ip41`, `twister` and `opus` have no entry in the bitstream table and reach the missing-bitstream error. This answers part of the open question in [arm-linux-packages.md](arm-linux-packages.md) for the 1.48.1 Linux 2.6 build: no `ip41` bitstream is chosen there, which agrees with the package listing, where only the legacy images carry `l1io_ip41`. The legacy and 1.44.0 builds of `l1ioInit` were not read. Whether those brick types need no FPGA loading, or load it elsewhere, is not settled by this routine.

- **GPIO access** (`l1ioGpioInit` `0x116c3c` 132 bytes, `l1ioGpioWrite` `0x116eac` 172, `l1ioGpioRead` `0x116f58` 172, `l1ioGpioIntSet` `0x117004` 172, `l1ioGpioIntGet` `0x1170b0` 172, error mapper `0x117300`). `l1ioGpioInit` opens `/dev/l1io_gpio` (character device 201:0) read-write and keeps the descriptor in a global; failure is logged as `l1ioGpio open error`. The other routines return the error code `-0xc1c` when the descriptor is negative, otherwise build a two-byte record and call one ioctl on it: write is request `0x40046700` with the record (byte 0 = byte 3 of the pin descriptor argument, byte 1 = value); read is `0xc0046701` with byte 0 only, then returns byte 1 through the result pointer; interrupt-set is `0x40046706` (pin, value); interrupt-get is `0xc0046707` (pin in, value out). The pin descriptor's fourth byte is the pin number. An ioctl failure is mapped by `0x117300`: errno 14 (EFAULT) becomes `-0xc1d`, errno 22 (EINVAL) becomes `-0xc1e`, any other errno is logged as `l1ioGpio error: %s` and becomes `-0xc1f`. Established. The kernel side of device 201 is not in this package's files.
- **`L1LogInit`** (`0x99038`, 176 bytes). Called once at start-up; if already initialised it logs `NET already initialized!` (the text names the wrong module) and continues. It creates the task `LOG_TASK` (entry `0x990e8`, with the arguments 0, `0xc18`, 15, 10 and 9 passed to `taskCreate`; the meaning of those arguments is not read). The task's body was not read. The FIFO it serves is `/dev/l1log`, the one `l1log` writes. Inferred (the FIFO link is by name).
- **`L1NetInit`** (`0x981b4`, 408 bytes). Creates the router queue `NET_WQUE`, the semaphore `NET_WSEM` and the tasks `NET_WTSK` and `NET_RTSK`, and starts a TCP connection to the L2 (`SocketMakeInetConnection`), logging `NET: waiting on open [connecting to L2 @ %s]` to the NVRAM log. A failure to create the queue is logged. The task bodies and the retry loop at `0x983e4` were not read. Inferred.
- **`L1ReqInit`** (`0xc60c8`, 356 bytes). Creates five semaphores (`REQ_SEM1` to `REQ_SEM5`, each initial value 1, flag argument 9), registers the router task number 6 (`IRouterInitID(.., 6, 0)`) and registers the request handler `L1ReqIRouter` (`0xc622c`, 26,788 bytes) for the destination selector `0x0ffff006`. A registration failure is logged. Established. `L1ReqIRouter` itself, the request catalogue's dispatcher, is the next thing to read; only its opening was read: it takes the brick type, decodes the first argument (a word, or through `IRArg` when the argument is not immediate), resolves the slab and sub-channel (`SysComGetSlab`, `SysComGetSubc`, and a slot-memory lookup `vramSlotGet`), and then compares masked fields of one word with `0x1000`, `0x2000`, `0x3000`, `0x4000` and `0x5000` and takes a semaphore (`semTake`; a failure logs `can't obtain L1Req semaphore`). Which of the five semaphores each value selects was not traced.
