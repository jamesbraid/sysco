# Out-of-band messages (`oobmsg`), the command router (`route`) and the stack's routing routines

`mmscfw.bin`, IRIX 6.5.30 (MMSC 2.3). Context: [rack-election.md](rack-election.md), [remote-link.md](remote-link.md). Sizes count code up to the last `ret`.

## Out-of-band message

A short binary frame that a console peer sends to the MMSC on the serial input it watches (`csSysInWatchOOB` calls `oobProcessMsg`, call at `0x11fffd`), and that the MMSC answers on the same descriptor. It has nothing to do with the election or the Ethernet.

Format, from `oobChecksumMsg`, `oobProcessMsg` and `oobSendMsg`: byte 0 prefix `0xa0`; byte 1 command or response code; bytes 2 and 3 the payload length `n`, high byte first; `n` payload bytes from offset 4; one checksum byte at offset `4 + n`. The checksum is the low byte of the sum of bytes 1 through `n + 3` (the prefix is not summed). The frame occupies `n + 5` bytes.

Canned replies (five-byte records in data at `0x1b1030`, each a complete frame with `n = 0` except the last): bad checksum `a0 04 00 00 04` (`0x1b1030`), bad command `a0 02 00 00 02` (`0x1b1035`), OK `a0 00 00 00 00` (`0x1b103a`), and the version reply at `0x1b103f`, whose bytes `a0 00 00 01 01` are followed by the byte `0x02` at `0x1b1044`: code 0, length 1, payload 1, checksum 2.

Request codes handled: 0 (reply OK), 1 to 11 (a graphics command), 0x3d (an MMSC command line in the payload, refused with the bad-command reply when bit 18 of the user's option word at user +0x3c is set), 0x3e (reply with the version record); anything else gets the bad-command reply.

- `oobChecksumMsg` (`0x12a1a4`, 71 bytes). Returns the checksum of the frame passed in as described above. Established.
- `oobProcessMsg` (`0x12a2b4`, 361 bytes). Arguments: a name used in log text (the console's name) and the received frame. A null frame or a prefix other than `0xa0` is logged and dropped without a reply. A checksum mismatch is logged ("... invalid checksum, was %x should be %x") and answered with the bad-checksum frame. Otherwise logs the request under bit 3 of the byte at `0x1e2339`, then dispatches on byte 1 as above. All replies are written to the descriptor at the first word of the structure at user +0x6c. Established.
- `oobSendFFSCCmd` (`0x12a444`, 253 bytes). Runs the payload as an MMSC command (`cmSendFFSCCmdNoPB`) and builds a reply frame with code 0 whose payload is the command's reply text plus its terminating zero. If the reply text contains the user's piggyback character (the byte at user +0x92), the text after it is saved and, after the reply is sent, run as a further command with `crProcessCmd`; the text is cut at that character unless the user's mode is 3. Sends with `oobSendMsg`. Established.
- `oobSendGraphicsCmd` (`0x12a564`, 257 bytes). Formats `rack . graphics_command %p %p` with the request and a local output pointer, runs it with `cmSendFFSCCmd`, and takes the reply text after the user's other piggyback character (the byte at user +0x93; the whole text if absent). If the text does not begin `OK` it is sent as a frame with code 5 (length = text + terminator, checksum appended); in the `OK` case no new frame is built and the output frame is sent as it stands. Established; the contents of that output frame in the `OK` case was not traced.
- `oobSendMsg` (`0x12a6b4`, 148 bytes). Writes `n + 5` bytes (`n` from the frame's length field) to the descriptor, looping on short writes with the `OOBMSG_WRITE` tune value (`ffscTune`+0x78, default 500,000) passed to `timeoutWrite`. A negative write logs "Timed out writing OOB message" (errno 4) or "Write to FD %d for OOB msg failed" and returns -1. Returns 0. Established.

## Command router (`route`, the MMSC object)

Task `tRouter` (priority 100, stack 20,000, started in `ffscInit` at `0x126f1e`) takes commands from every local console, from every connected remote rack and from the two MSC bays, and sends each to the racks and MSCs it names.

- `router` (`0x12be44`, 1,674 bytes). The task body. Sets `routeRebuildResponses` and `routeReEvalFDs`, clears the reboot and base-I/O flags and counts one request descriptor. Each pass: (1) if `routeRebootFFSC` is set, sends `SHUTDOWN` to user records 1, 2 and 4 (`ShutdownWarning`; record 4 is skipped when its flag bit 1 is set), waits `stallTime` ticks where `stallTime` is 60 times the rack ID (the code is `rackID * 15 * 4`), logs it and calls `sysReboot`; the stagger keeps racks from rebooting together. (2) If `routeCheckBaseIO` is set, sleeps for `ffscTune`+0x74 (`CONS_MODE_CHANGE`) and twice that, and re-checks the system console. (3) If `routeRebuildResponses` is set, fills the 23 per-rack response slots (index 0 to 22, from `users`: slot for the local rack is the console's, the others the remote users') and the two MSC slots, then clears the flag. (4) If `routeReEvalFDs` is set, rebuilds the descriptor set from the listener pipe `L2RMsgFD`, every user whose flag bit 0 is set (descriptor at the input object's +0x14) and every MSC bay in state 1, then clears the flag. (5) `select(256, set)`; error -1 logs "Error on select in FFSCmain" and ends the task. (6) For each ready MSC bay, `elscProcessInput`; a non-zero result logs "No longer listening to MSC" and drops it. (7) For each ready local user, `ProcessUserCommand`. (8) If the listener pipe is ready, `remAcceptConnection`; a return of -2 re-evaluates, a rack ID above 0x17 is logged "Rejecting remote request - invalid rack ID" and the descriptor closed; otherwise the descriptor is placed in the slot of that rack, the user record applied with `userInsertUserInfo`, `ProcessUserCommand` run once and the descriptor closed. The loop ends, logging "route task is exiting", when no descriptors remain. Established.
- `ProcessUserCommand` (`0x12c5e4`, 277 bytes). Reads one line from a user with `msgRead` (timeout `RI_REQ`); a bad or incomplete message is logged and dropped; otherwise logs it ("<user> COMMAND: <line>" for user mode 3) and calls `ProcessCommand(line, user)`. Returns 0, or -1 when `msgRead` fails. Established.
- `ProcessCommand` (`0x12ca94`, 2,835 bytes). Arguments: a command line and its user. An empty line becomes `RACK LOCAL MMSC` or `RACK LOCAL NOP`. `destParse` splits off the destination (a byte per rack 0 to 22 whose bits 0 and 1 name the two MSC bays, bit 7 all bays, plus a flag word); an unparseable destination answers `R<rack>:ERROR DEST`; a missing default answers `R<rack>:ERROR NODEST`. Clears the 25 response slots, runs the command locally with `cmdProcessFFSCCommand`; a negative result answers `ERROR CMD`; result 0 is a purely local command, answered with the local response text prefixed `R<rack>:`. For results 1 and 2 it creates `outConnsSem` and `outConnsDoneSem` if needed, counts the racks other than the local one in the destination, spawns one task `tRmtcmd<rack>` (priority 100, stack 5,000, entry `remStartRemoteCommand`) per such rack, and when the local rack is also named and the result is 2 sends the command to its MSC bays with `routeProcessELSCCommand`; it then waits on `outConnsDoneSem` until the senders have finished. Result 3 is a command that needs no fan-out. If the user wants no reply it closes the response descriptors and returns. Otherwise it `select`s on the response descriptors with a timeout of `RI_RESP` (or `RO_RESP` when a slot is marked as needing the longer wait), reads each reply with `msgRead` as it arrives, closes the descriptors, turns a timed-out slot into `R<rack>:ERROR TIMEOUT (ProcessCommand)` or `ERROR BADRESP`, and concatenates the replies in rack order, MSC replies (formatted `R<rack><bay letter>:` with each reply cut at the first carriage return) taking the local rack's place. The reply text is then written to the user's reply channel. Established as read; the destination parser and the message framing are other routines.
- `routeDoAdminCommand` (`0x12c4d4`, 22 bytes). Calls `ProcessCommand(line, users[5])` (the dword at `users`+0x14, the administrative user). Callers: `elscPrintMsg`, twice. Established.
- `routeProcessELSCCommand` (`0x12c4f4`, 143 bytes). Arguments: command text, user, destination index. For each MSC bay named for the local rack, sends the user's password (`elscSendPassword`, from user +0x20) and the command (`elscSendCommand`); a bay that is not named but whose destination byte has bit 7 set gets the reply `OFFLINE` and state 0xb. Callers: `cmdELSC`, `cmdPWR`, `ProcessCommand`. Established.
- `ShutdownWarning` (`0x12d5b4`, 23 bytes). `userSendCommand(user, "SHUTDOWN", 0)`. Established.

## TCP/IP stack routing routines (`route.o`, second object)

The second object named `route.o`, at `0x1a7ab0` to `0x1a8188`, is part of the stack inside the image, not of the MMSC's own router: its callers are `ip_output`, `ip_forward`, `icmp_input`, `in_control`, `in_pcbconnect`, `tcp_mss` and `soo_ioctl`, and its callees are `splnet`, `splimp`, `splx`, `ifa_ifwithnet`, `ifa_ifwithaddr`, `ifa_ifwithdstaddr`, `m_get`, `m_free`, `tickGet`, `bcmp`, `panic`, and function pointers taken from the radix-tree head. It has the shape of the BSD route table code (host and network hash `rthost`, `rtnet`, `wildcard`, `rtstat` counters, `rttrash` count). Only the call lists and the first instructions of each routine were read, which fixes who calls them and what they call; their bodies were not compared with BSD `route.c`. None is involved in the election or the peer link. Inferred, from the call lists.

- `rtalloc` (`0x1a7ab0`, 394 bytes). Looks a route up through the table; calls `splnet`, `bcmp`, `splx`, updates counters in `rtstat`. Inferred.
- `rtfree` (`0x1a7c50`, 60 bytes). Drops a reference; calls `panic("rtfree")`, `m_free`, decrements `rttrash`. Inferred.
- `rtredirect` (`0x1a7c90`, 391 bytes). Applies an ICMP redirect: `ifa_ifwithnet`, `ifa_ifwithaddr`, `rtalloc`, `rtinit`, `rtfree`, `tickGet`. Inferred.
- `rtioctl` (`0x1a7e20`, 41 bytes). A single call to `rtrequest`. Established (read in full, 41 bytes).
- `rtrequest` (`0x1a7e50`, 712 bytes). Adds, deletes or changes a route: `splimp`, `ifa_ifwithdstaddr`, `ifa_ifwithaddr`, `ifa_ifwithnet`, `m_get`, `m_free`, `bcmp`, `tickGet`, `splx`. Inferred.
- `rtinit` (`0x1a8120`, 103 bytes). Zeroes a request block with `bzero` and calls `rtrequest`. Inferred.
