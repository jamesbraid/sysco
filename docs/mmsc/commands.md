# MMSC command catalogue

The typed command set of the MMSC firmware, read from the command table in the 6.5.30 image
(`root/6.5.30/usr/cpu/firmware/mmscfw.bin`, MMSC 2.3). The table itself is generated by
[scripts/mmsc_commands.py](../../scripts/mmsc_commands.py) into [commands.tsv](commands.tsv),
one row per table entry. Handler bodies for ten commands are read in [command-routines.md](command-routines.md). Regenerate it after any change to the script:

    tools/re-run python3 scripts/mmsc_commands.py

## The table and the dispatcher (established)

Routines are named by address. The image's symbol names are not used here, so the rows can be
read against the image directly.

- The table is at 0x1b07a8 in the image's data (found through the symbol table): 60 entries of 12 bytes
  (name pointer, handler pointer, help-text pointer), ended by an all-zero entry. The name is
  the command word as typed, short form included (`AUTH`, `CONS`, `?`).
- 52 distinct handler routines. Eight entries share a handler with another entry: the short
  names `AUTH` and `CONS`, the aliases `MMSC` and `MSC` (which share handlers with `FFSC` and
  `ELSC`), `MMSG` (shares `EMSG`), `RESET_FFSC`, `REBOOT_FFSC` and `RESET_MMSC`, and `?` (shares
  `HELP`). Entries without help text (`AUTH`, `CONS`, `DEBUG`, `EMSG`, `ELSC`, `FFSC`, `NOP`,
  `PAS`, `PWR`, `MEM`, `TTY_REINIT`, `GRAPHICS_COMMAND`, `IPADDR`, `REBOOT_FFSC`, `RESET_FFSC`
  and others) are listed in the TSV with `help` set to `no`.
- The dispatcher is the routine at 0x111d30. It upper-cases the first word of the line, copies
  the line, splits it at spaces and tabs with the tokenizer at 0x184580, then walks the table comparing the
  word with the string-compare routine at 0x1840a8 in table order. On a match it calls the handler with a pointer to its
  local copy of the line, the session pointer and a third argument. The dispatcher itself
  checks no authority level. Read in full (66 instructions).

## Authority levels (established from the table; the threshold reading is inferred)

The authority table at 0x1b0aac holds name and value pairs: `BASIC` 100, `SUPERVISOR` 500,
`SERVICE` 1000, and `MSC` and `ELSC` -1 (not user levels). The session structure holds the
current value at offset 0x20.

- The AUTHORITY handler compares the requested value with 499 and 999 and asks for a stored
  password, one for each band, before it raises the level. Levels above 499 need a password.
  The compare reading is inferred from the instructions; the handler's full listing has not
  been read end to end.
- The default level at session start is not read here.

## Per-command permission, as read

"Level" means a compare of the session value at offset 0x20 that the handler reaches. The
rows come from the generated TSV (`levels` column), which takes the first compare after each
read; a check written differently would not appear.

| Commands | Check found in the handler | Grade |
|---|---|---|
| COM (subcommands only; plain `COM <p>` shows parameters) | level above 999 required; otherwise `ERROR AUTHORITY` | established (routine read in full) |
| DEBUG, DIRECT, DOWNLOADER, FLASH, IPADDR, NAP_TIME, OPTIONS, RACKID, SCAN, SETENV, UNSETENV, TTY_REINIT, RESET_NVRAM, RESET_MMSC (also `REBOOT_FFSC`, `RESET_FFSC`) | level above 999 required on the first compare; the path that returns `ERROR AUTHORITY` is in the handler | established for the compare; the exact subcommand split is not read for each |
| STEAL, UNSTEAL, SWAPCONS | level above 499 required | established for the compare |
| PASSWORD | a compare of 499 against a value from the handler; the messages `ERROR PERMISSION` and `User %s not authorized to change %s password` show that the rule depends on the user and the password type | the rule itself is unknown; not read |
| BS, END, ESC, KILL, EXIT, CECHO, EMSG/MMSG, RMSG, DEST, PAGER, LOG, PARTxxx, PRINTENV, PWR, MEM, PAS, NOP, VER, HELP, ARBITER, MACADDR, ELSC/MSC, FFSC/MMSC, CONSOLE/CONS, RAT, MMSG and the rest | no session-level read in the handler's reachable code; some call routines that take the session (for example the routines at 0x12fa28 and the remote-acquire routines of the ELSC and FFSC paths) whose checks were not read | established as "no read in the handler"; the callee checks are unknown |

Items that still need a read: the PASSWORD rule, the callee checks for the ELSC/MSC and
FFSC/MMSC paths (remote acquisition), and the exact subcommand split for the level-999 rows.

## Syntax and emitted strings

The `usage` column of [commands.tsv](commands.tsv) carries the syntax words from the help text,
and the `responses` column the short response forms each handler can emit. Both are read from
the image, so they are established as shipped. Long help blocks and other literal text are
not copied here.

Common response forms seen in the handlers: `OK ...`, `R%ld:OK ...`, `ERROR ARG`,
`ERROR AUTHORITY`, `ERROR PERMISSION`, `ERROR BUSY`, `ERROR DEST`, `ERROR NOTAVAILABLE`,
`ERROR INTERNAL`, `OK;STATE ...` for mode and state queries.

## Cross-check with the public owner's guides

- Origin2000 Rackmount Owner's Guide, 007-3456-003, chapter 7 ("Using the System Controller"):
  the guide describes the MMSC front-panel menu (Focus, Action: Power Up, Reset, Power Down)
  without a password, names software reset, NMI, power-off, and voltage margining as diagnostic
  port functions, and says a software password controls access to that port. It gives no typed
  command syntax, so none of the 60 entries can be confirmed or refuted against it. The
  printed-page text was read from a web copy through a summary tool only; the page images
  could not be rendered here.
- Onyx2 Rackmount Owner's Guide, 007-3457-005: not checked.

Result: the owner's guide documents no typed MMSC command syntax, so the typed catalogue rests
on the image alone.

## Exposure

A library search for "MMSC RESET_NVRAM" returned snippets from restricted vendor source for the
MMSC command module and a document titled as the MMSC command language. One snippet was a
function prototype line from that source. None of those files was opened, and nothing from them
is written here. Later searches used the public-document filter only.
